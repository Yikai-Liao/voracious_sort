# Lookup group-position screen

UnifiedLookup inherits all UnifiedPrepared policy flags, including the fixed offline 16 MiB threshold, and the same one-varying-bit Block gate as the scalar/arithmetic controls. It keeps the original radix range, scratch budget, recycling, pass work, fixup and compaction. Records wider than one machine word use the original scatter loop. No key-width dispatcher or independent sorter is added.

Arithmetic Batch and Lookup differ only in group-local position calculation. Four label bits form a 0..15 pattern. A 16-entry u32 constant table encodes the selected-bucket preceding-record counts for positions 1/2/3 and total high count; position 0 has offset zero. The table is 64 source-level constant bytes, with no allocation or preparation pass. Destinations and store order are exactly the four scalar destinations. Both capacities must remain strictly greater than four, so no block refill occurs inside the group. The unchanged scalar fallback handles near-full buckets, small blocks and tails.

Both helpers are inline(never), with no const BYTE parameter. Only the arithmetic/lookup choice is a const parameter of that helper; it does not multiply the full step body or its sixteen byte dispatches. Each eligible binary pass retains its one first-live-label probe, counted by actual label evaluations. Direct tests compare all four backends, exact label trace and compact/tail work; they cover irregular labels, nonzero common bits, all tails, odd block sizes, wide fallback and u64 high-bit masks.

Before timing: 30 frontier tests with frontier_work, generator test and all-target/all-feature checking; narrow optimized ELF freeze and machine-code inspection. Debug info is disabled for correctness builds, with assertions and overflow checks enabled. Build uses CARGO_INCREMENTAL=1, native CPU, release CGU 16, jobs 6 and the existing optimized cache. Full library tests cover wide types; the timing harness feature only instantiates four narrow layouts.

The first screen is fixed before viewing results: n 1048576, B 64, seed42, u8/u16/u8_id8/u16_id8, uniform/sparse, fourteen repetitions and seven slots (Pa, Prepared, arithmetic Batch, Lookup, frozen LSD, Stable MSD, Pa). This is 784 rows and one complete rotation with paired reverse directions. Seed 42 sparse inputs use the unchanged seeded shuffle. CPU 2, restored allocation, full stable oracle and Pa A/A apply. No compilation/testing during timing. Per-cell paired Lookup/Batch identifies the table effect; Lookup/Prepared and Lookup/Stable determine whether the existing narrow guard is fixed. A negative screen ends this candidate. Seed 20261018 remains unseen.
