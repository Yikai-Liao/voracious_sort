# Block MSD 后续优化：数学分析与实验计划

日期：2026-10-15。基线固定为 [749ca4d163cbfa93a9e47d67c03db80d8b71bc22](https://github.com/Yikai-Liao/voracious_sort/commit/749ca4d163cbfa93a9e47d67c03db80d8b71bc22)。

本文替代上一份以 04e850a 为基线的下一轮计划。依据是最新组合报告、关键实现及独立数学推导；没有重新执行仓库测试或原生性能实验。报告中的时间属于已有实验，不是本文新测的结果。

## 1. 结论先行

下一轮不把 `hybrid_mono` 直接升为默认控制版本，也不继续扩大组合开关。先补齐可归因的工作账本，再沿以下方向逐项验证：

1. **连续内核：合并重复的元数据数组，核对同等工作下的内核成本。** 这是影响现有小记录路径、改动较小的方向。
2. **归位：用空位路径与置换环旋转减少实际记录写入。** 有明确的写入量证明，但收益取决于归位在总时间中的占比。
3. **回退：接续已算好的根统计。** 删除确定的重复工作，同时保留真正有价值的有序检查。
4. **单调性检查：与必需的 histogram 合并，独立消融。** 消除新增的一遍提取，不承诺比较与依赖免费。
5. **准入：先建立真实空间账本，再修订连续后端的准入。** 空间合法、缓存合适、摊还工作受控是三种不同条件。

连续内核 ping-pong 和子节点变化位摘要保留为有条件的后续研究。前者对当前百万随机 u32 的典型单层 cached 子树**不减少写入**，不应被包装成主问题的解决方案。

最终目标仍是跨尺度优于原版 MSD，同时保持稳定性和清楚的空间合同。现有证据不支持“每个输入必胜”，也不支持靠当前候选的排列组合即可完成目标。

## 2. 最新结果怎样改变判断

来源：[组合实验报告](https://github.com/Yikai-Liao/voracious_sort/blob/749ca4d163cbfa93a9e47d67c03db80d8b71bc22/experiments/block_msd/combined_experiment/REPORT.md)、[聚焦数据](https://github.com/Yikai-Liao/voracious_sort/blob/749ca4d163cbfa93a9e47d67c03db80d8b71bc22/experiments/block_msd/combined_experiment/focused-comparison.csv)。

### 2.1 组合并未带来广泛、可相加的收益

- `hybrid_mono / local_free`：primary105 几何均值 0.9806；original75 为 1.0052。
- 加入两个 digit 场景后约快 1.94%，原有集合约慢 0.52%。不能称为原有任务的普遍提速。
- `local_free → hybrid` 同时改变 carry、gate 和 fallback。当前计时没有覆盖所有中间版本，不能分解每一项贡献。
- `hybrid → hybrid_mono` 才是本轮直接隔离单调性检查的对照。

### 2.2 小记录与大记录需要解释不同成本，不能先写类型分派表

百万随机数据，同一轮聚焦测量，单位 ms：

| 方法 | u32 | wide32 | large128 |
|---|---:|---:|---:|
| local_free | 10.020 | 23.492 | 66.521 |
| hybrid_mono | 10.031 | 22.672 | 65.902 |
| stable_fixed | 8.705 | 29.090 | 109.137 |
| Block LSD 512 | 3.348 | 77.519 | 91.732 |
| Rust stable | 14.596 | 42.064 | 164.785 |

小记录 MSD 尚有明显缺口，大记录 MSD 已有真实优势。宽记录也同时改变了键宽或载荷，不能把表格全归因于 `sizeof(T)`。`std_stable` 是本次 Rust 标准库稳定排序，不能把它直接改称 Timsort 的实测。

### 2.3 “少写很多”仍不等于“快很多”

百万 `digit_grouped` u32 的单调性证明确实省掉根节点 n 条 scatter 与 2,097,088 条归位写入，但总时间仅从 9.436 降至 8.866 ms，约 6%。与此同时还增加了单调性扫描，并改变了临时工作区与缓存状态。满足契约时，这个恒等根分桶的子切片内容、顺序与地址范围相同。

因此既不能说归位只占 6%，也不能继续按减少的写入比例预测加速。必须分别测扫描、元数据、scatter、归位、连续内核与叶子。

`large128` 的末尾逆序反例从 55.715 增至 61.067 ms，约慢 9.6%。新增识别本身存在可重复的最坏成本。

### 2.4 当前计数还有一个缺口

gate 拒绝后调用 Stream，丢弃其返回的统计。Hybrid 的局部归位计数不包含 fallback 内部归位。**计时和 heap 包含 fallback，局部工作计数却不完整。** 后续不能用局部计数为零推导总搬运为零。

## 3. 先建立可检验的成本模型

设一个节点有 m 条记录，记录宽度 e，桶数 σ，块长 b。

分别统计：

- 有序检查、变化位、histogram、单调性检查访问的记录数。
- histogram 清零槽数，以及分配次数和请求字节数。
- scatter、尾部保存、归位、copyback 的记录读写数。
- 连续子树的实际 digit 层数与各层节点大小。
- 叶子调用数、长度分布、比较次数或受控的比较路径。
- fallback 完整工作；与 local 工作合并但不重复计数。

不能把一次 swap 记成一次写入，也不能把“写入条数”混同 CPU 指令数或实际内存总线流量。

典型两层 uniform 路径的简化账本是：

`block 根 scatter n + 根归位约 2n + cached scatter/copyback 2n ≈ 5n`

普通两层 copy/scatter 的对应记录写入约为 4n。账本不包含全部叶子、扫描、元数据和缓存写分配；更不是算法下界。

### 3.1 用 Amdahl 检查方案是否有机会达标

若某阶段占原总时间 f，阶段耗时变为原来的 q，则总时间比例理想化为：

`T_new / T_old = 1 − f(1−q)`。

以 local_free 的 10.020 ms 为起点：

- 达到 stable_fixed 的 8.705 ms，需要总耗时下降约 13.1%。
- 达到 ordinary 的 8.275 ms，需要下降约 17.4%。
- 若归位阶段自身恰好减半，则它原本至少要占约 26.2%／34.8%，才可能独自达到这两个目标。

这只是必要的可行性检查，不是已测阶段占比。把约 5n 写入降到约 4n，也不能直接称总时间减少 20%。更不能用这种局部改动解释与 3.348 ms LSD 的全部差距。

## 4. 方向 A：先简化连续内核的真实工作

源码：[node_local.rs](https://github.com/Yikai-Liao/voracious_sort/blob/749ca4d163cbfa93a9e47d67c03db80d8b71bc22/experiments/block_msd/src/node_local.rs#L800-L875)、[stable_baseline](https://github.com/Yikai-Liao/voracious_sort/tree/749ca4d163cbfa93a9e47d67c03db80d8b71bc22/experiments/block_msd/src/stable_baseline)。

### 4.1 counts 与 ends 无须同时存在

当前非平凡 cached 节点持有 counts、heads、ends 三个数组。计数完成后，把 counts 原地改为累积终点：

`E[r] = Σ(t≤r) count[t]`。

再令 `H[0]=0`、`H[r]=E[r−1]`。scatter 保留以下检查：

- digit 在桶索引范围内。
- 写入前 `H[r] < E[r]`。
- 完成后每个 `H[r] == E[r]`。

子桶长度可由 `E[r]−E[r−1]` 得到，因此不再需要原始 counts。零桶也自然成立。

**可证明的收益：** 每个非平凡 cached 节点少一个长度 σ 的数组及一笔对应分配；不改变树、稳定顺序和目标位置。原来填充 ends 的 σ 次写入改为原地覆盖 counts，不能称这些前缀写入也被删除。减少容量与分配，不等于减少 histogram 清零或保证总耗时显著下降。

第一轮只做这项转换，不同时建立全局 workspace。它比“加一层缓存对象”更直接。

### 4.2 跨节点复用元数据是第二项独立实验

设 H 为所有尝试过的 histogram digit 数，V 为实际 scatter 节点数。现代码的相关 Vec 分配次数为 `H+2V`，另有 cache 入口记录 scratch。

原地累积终点后可降为 `H+V`。再复用每层的终点行与一份当前 heads，才有机会把数组分配次数降到与深度有关，而非与节点数有关。

但仅在单个 cache 入口里复用，无法消除 256 个互相独立 cache 入口之间的分配。若要跨入口复用，元数据必须在排序的外层作用域存活，并准确计入峰值。不要新增 Engine 或薄转发层。

父终点数组仍要用来枚举子桶，不得与子 histogram 覆盖复用；heads 在 scatter 结束后不再需要，可以顺序复用。保留容量会延长生命周期，不能一边保留大容量、一边按当前浅层长度计空间。

### 4.3 先对齐工作，再研究内核效率

现有两套内核并非只差根归位：

- cached：受检查的逐条 `arr → scratch` scatter，再 bulk copyback。
- stable_baseline：先复制，再使用其已有 scatter 内核；叶子调用形式也不同。
- 两者叶子阈值均为 128，但 `sort_by_key(into_key_type)` 与 `sort_by(partial_cmp)` 的调用和编译结果不能假定完全一样。

对 u32 固定相同节点输入、相同 digit、相同叶子区间，做内部路径对照。保留通用 extractor 的边界与初始化检查，不能以删除安全约束来“对齐速度”。不得把 baseline 的 Verge 预处理等总流程差异误归因于单一循环。

## 5. 方向 B：空位路径与置换环归位

### 5.1 为什么本实现可用块图模型

当前分桶 assembly 已把不同桶的边界拼成全局对齐的逻辑输出块。归位对象不是任意重叠的桶区间。

令 D 是原数组中的完整目标块槽，S 是当前完整输出块的物理源槽。每个源唯一、每个目标唯一，于是 `source → destination` 图的入度、出度都不超过 1，只可能是定点、路径、环。

该证明需要目录无重复和无遗漏。构造 inverse 时应在验证版本中检查同一物理槽未被重复登记，而非让后写 owner 静默覆盖前一个。

### 5.2 尾块先保存到最终位置

Arena 只注册原数组的完整块；原输入尾部在分桶前已迁至 scratch。最终尾部目标不与其他完整物理源槽重叠。

先复制最终尾块的有效记录至原数组尾部，再移除旧尾源的 owner。不能读取或复制未初始化 padding。这一步会为后续完整块图释放一个可能位于 D 的槽。

### 5.3 路径与环算法

路径从空目标槽开始，找到该目标需要的 source，复制入空位。若 source 在 D 中，它成为下一空位；若在 scratch，路径结束。

每条长度 k 的路径恰好写 k 个最终块。对旧算法中原本终止于空槽的路径，旧写入依处理顺序为 k 到 `2k−1` 个块；若该终点原本持有尚未归位的部分尾块，旧算法还可能交换这个尾 owner，块写入可达 2k。两版有效尾记录都还要写入最终尾部。尾先归位消除了这类中转，所以改进非负，但不保证每条路径都减少。

处理完全部路径后，scratch 中没有剩余有效完整块：scratch 不属于目标集合，拥有 scratch 源的分量必为路径，不能为环。因此可以借已有一个 scratch 块处理剩余环，无须新 payload 分配。

- 定点不动。
- 两块环保留 swap。
- 其他环：暂存一个块，制造空位，再沿路径式搬运完成环。

长度 k≥3 的环：

`旧写入 = 2(k−1)b`，`新写入 = (k+1)b`，包含临时保存。

k=3 持平；k≥4 少写 `(k−3)b` 条记录。两块环的特殊处理来自精确置换结构，不来自数组规模或分布标签。

### 5.4 空间与性能边界

复用已有 blocks、inverse 和 scratch，保持原工作区销毁时机；不新增 visited、全元素 index 或环向量。

写入不增加的证明不等于时间不增加。目录访问、环之间的局部性、bulk copy 的生成结果仍可能改变速度。首先只替换归位，不同时改变 scatter、cache 准入或 gate。

已用独立 Python 抽象模型检查 17,399 个注入映射：完整块数 0..5、scratch 槽数 1..2、块长 4、尾长 0/1/3。检查结果包括完整身份、owner 一致性、不读取完整块中的未初始化 padding、新写入公式及相对旧算法写入不增加。该模型覆盖允许尾源在数组槽的更广状态，不声称这些状态全部在当前 assembly 中可达。

这是有限状态的抽象验证，不是 Rust 实现、指针别名、panic 或原生测试的证明。实现仍须测试：定点、2/3/长环、多个环、scratch 路径、路径环混合、尾源位置、满 scratch、无完整块、尾长 1 与 b−1，并用原始身份校验稳定结果。

## 6. 方向 C：回退接续根统计，不能重新从头识别

源码：[gate 回退](https://github.com/Yikai-Liao/voracious_sort/blob/749ca4d163cbfa93a9e47d67c03db80d8b71bc22/experiments/block_msd/src/materialization_gate.rs#L168-L230)、[Stream 入口与统计](https://github.com/Yikai-Liao/voracious_sort/blob/749ca4d163cbfa93a9e47d67c03db80d8b71bc22/experiments/block_msd/src/combined_stream.rs)。

拒绝发生在 scatter 前。输入尚未改动，当前 counts、mask/shift、剩余位数已有准确含义。应通过内部入口把这些信息接续给 Stream 首个节点，不再重复 variation 和当前 histogram。

不为此设计公开通用协议，也不强制创建一组 Prepared/Outcome/Context 类型。先明确必要信息和唯一使用边界，再选择最简单的内部表示。

### 6.1 删除哪些工作，最多能省多少

拒绝节点形成不相交的子树前沿，因此 `Σ m_fallback ≤ n`。若每个拒绝根删除一次重复 variation 与一次重复 histogram，整个排序最多删除约 `2n` 条记录访问；不会连 Stream 子孙的扫描一起消失。

若后端原先会通过 ordered 快速退出，则不能宣称它原本必然执行了这两次扫描。此上界是对实际进入完整准备路径的节点计算的。

### 6.2 必须修正上一版计划的有序检查表述

只有初始根输入已经经过且失败的 ordered 检查，可以在输入不变时直接复用“非有序”事实。某个后代节点可能恰好有序，原 fallback 会发现并直接结束。

因此后代有序状态未知时保留检查；若它返回成功，直接完成该节点。不能因为“删除重复准备”而顺手删除后代真正的快速路径。

### 6.3 其他前提

- counts 对应同一切片、同一 extractor、同一 mask/shift。
- 已处理的高位前缀相同；跳过的 digit 已证明恒定。
- partial digit 的 width 规则不变。
- 若按剩余位数缩小 scratch 预留，需要重新证明 Stream 的 live-block 供应界；第一轮可先保留旧预留，只删除重复统计。
- 通用 extractor 必须保持一致的键语义；安全的可变 extractor 即使违反排序契约，也不能导致未初始化读取或越界写。
- fallback 统计并入总账，避免局部计数给出虚假的改善。

## 7. 方向 D：把单调性证据并入 histogram

### 7.1 精确条件与证明

令当前 digit 为 d_i，桶数为 c_r，桶起点为 `P_r=Σ(t<r)c_t`。稳定计数分配把第 i 项送往：

`p_i = P_(d_i) + #{j<i : d_j=d_i}`。

若 d_i 非递减，则所有更小 digit 都在 i 之前，加上此前相同 digit 的数量恰好是 i，故 `p_i=i`。反之，若稳定分配是恒等置换，输出 digit 已有序，原 digit 必须非递减。

所以“当前 digit 非递减”与“本轮稳定分桶不搬任何记录”等价。它不证明完整 key 已有序，子桶仍须递归。

### 7.2 独立扫描的最坏情形不可消失

成功和最后一对才逆序都要检查 n 项。后者省不掉任何分桶，新增 Θ(n) 访问。

没有覆盖全部位置的先验证据时，抽样不能准确接受恒等置换：未观察的位置仍可隐藏逆序。抽样只能保守拒绝或决定是否继续验证。

### 7.3 融合可消除访问，但不能消除运算

histogram 提取 d_i 时同时维护 previous 和 violation：

- 新增全量记录访问：0。
- 新增 extract 调用：0。
- 新增比较：最多 n−1。
- 新增状态：O(1)。

这样消除了最后逆序时“额外完整走一遍”的问题，但比较、依赖链、寄存器压力及编译器优化损失仍可能使 histogram 变慢。

先测试最简单融合；若它确有普通随机路径回退，再独立考虑固定小 tile：tile 内更新证据，tile 边界发现失败后，其余部分回到原 count-only 循环。不能为了规避一个负例不断增加类型门槛。

可组合证据为 `(empty, first, last, ordered)`：

`ordered(A||B)=ordered(A) ∧ ordered(B) ∧ last(A)≤first(B)`。

只有 first/last 或 min/max 不足以证明块内有序。禁止用不完整证据跳过分桶。

## 8. 方向 E：明确空间合同后再放宽连续准入

256 KiB 当前是工作集启发式，**不是整个排序的硬辅助内存上限**。把输入体积算入缓存工作集是合理的，把它算成辅助分配则不对。

### 8.1 按生命周期计算

设 cached 入口长度 M，记录宽 e，最大剩余层数 d，各层桶数 σ_j；H 为外层仍存活的 histogram 容量字节。

一份 M 项 scratch 在整个 cached 子树内存活。祖先 counts 存活，当前 heads/ends 在递归前释放。

当前实现某个 scatter 阶段的请求 heap 上界形如：

`H + M e + w Σ(i≤j)σ_i + 2wσ_j`，再计真实容量差异。

叶子阶段则为：

`H + M e + w Σ(ancestor)σ_i + W_leaf_heap`。

取阶段最大值，而非把互斥阶段全部相加。固定 σ 时，一个保守元数据界是 `(d+2)σw`，小于原启发式里的 `3dσw`。采用方向 A 的两数组结构后还要重新核算，不能继续沿用旧公式。

叶子 std 排序的 heap、stack 必须分别核定；“≤128项”和固定 8192 allowance 不是标准库行为的数学证明。Vec 的 IntoIter 在遍历子节点时仍保留 backing allocation。

### 8.2 整体预算与比较方式

node-local 父分桶工作区在进入子节点前已释放；外层 counts 仍在。Stream fallback 另有深度相关 scratch、目录和 Writer。

若定义硬预算 B，则所有候选，包括 fallback，都必须满足：

`当前保留字节 + 所选后端的最大新增同时存活字节 ≤ B`。

“满足 B”与“每个输入实际峰值不高于旧版”是不同声明。后一种必须比较真实生命周期或旧版的必付同时存活空间，不能拿旧版宽松上界代替。

固定 b 时，O(n/b) 目录仍是关于 n 的线性空间。若讨论平方根空间，必须同时说明 b 如何随 n 变化，并计入反向增长的 O(σbe) scratch；本轮不顺便改块大小。

### 8.3 gate 的证明不能与新的准入脱节

当前势函数：

`ψ(m)=0 (m≤128)`；否则 `ψ(m)=m[1+ceil(log2(ceil(m/128)))]`。

接受条件为 `m≤4[ψ(m)−Σactive ψ(child)]`。由于 ψ(m)/m 非递减，分割后子势之和不大于父势；沿树相消可得：

`Σaccepted m ≤ 4ψ(n)`。

单调跳过节点消耗非负势差但不收费，因此不破坏此上界。这个证明约束的是接受的 materialization 体积，不约束扫描、cached、叶子及 fallback 的全部时间。

反例：忽略 cache 完成时，257→256+1 的势差为 259，轻易通过；256→255+1 的势差为 2，拒绝。它有 dyadic 跳变，不能当平滑的均衡度指标或耗时预测器。

若新空间预算依赖祖先占用，gate 声称某子节点能进入 cache 并将其势置零，必须保证该子节点到时真的可进入。否则“已完成”的承诺失效，旧摊还证明也失效。需要预留或使用对未来上下文仍成立的充分条件。

## 9. 有条件保留：cached ping-pong

设固定 cached 树的非恒等 scatter 节点大小和为 `S=Σm_v`。当前记录写入为 2S，不含叶子排序内部写入。

交替原数组和 scratch 的角色，终止时只把仍在 scratch 的区间归回原数组。设这些终止区间总长为 O，则：

`W_new=S+O`，`O≤M`，且 `O≤S`，所以 `W_new≤2S`。

只有实际 scatter 才翻转奇偶；恒定 digit、恒等分桶不能翻转。终止区间互不重叠，每个区间最多归回一次。零 scatter 时 S=O=0；按每条记录经历的实际 scatter 次数 d_x，可进一步写为节省量 `S−O=2Σ floor(d_x/2)`。

**关键负结论：** 只有一层 scatter 后全部进入叶子时，S=M、O=M，完全不省记录写入。当前百万随机 u32 的典型 cached 子桶正是此形状。因此先统计实际深度，不作为主优先级。

实现必须使用与原数组区间对齐的 scratch 子切片；不能沿用可重用的 scratch 前缀，否则会覆盖尚未处理兄弟的有效数据。singleton、bits==0、全相同、最后不足一个 digit 等终止情况都要归回。不能只递归 count>1 后忘记仍在 scratch 的单元素。

scatter 完整验证之前不能把未初始化空间当成有效 T。scratch→arr 中途 panic 可能改变原数组的元素多重集；若要保留 panic 时的 permutation 语义，需要独立恢复保护及证明。避免以一个表面简单的双缓冲改写引入更难维护的所有权问题。

## 10. 暂不推进的方向

- **更多分布分类器或 dtype/长度选择表：** 当前候选的最优组合仍不能覆盖全部缺口。
- **直接把 gate 当最快后端预测器：** 势函数证明不了这一点。
- **给 cached 无条件补 OR/AND 子摘要：** 会新增键转换、每条记录更新与每层存活表。256 桶、128位键的两份摘要仅 payload 就有 8192 字节/帧；先证实重复扫描值得付这个价。
- **稀疏 histogram/epoch table：** 256 槽本来很小，额外 tag、分支、列表不一定便宜。
- **无条件去掉安全检查或替换 extract：** 不能改变通用接口的内存安全要求。
- **继续 prefix/joint/minority 的大组合：** 最新结果没有支持普遍纳入；保持独立控制即可。
- **立即对齐/展开/内联调参：** 先确认同样工作为什么更慢，不用代码布局偶然收益掩盖结构问题。

## 11. 实验顺序与淘汰标准

### 阶段 0：冻结和补证据

- 冻结本提交全部原始数据，不与 04e850a 的绝对时间拼接。
- 控制 C 采用 local_free。若要选择 local_carried，先补独立计时，不能从 hybrid 的表现倒推其收益。
- 保留 hybrid/hybrid_mono 为已知组合对照，不直接当新默认。
- 新诊断包含 fallback 的总工作及 cached 深度、元数据分配、叶子长度；计时关闭新增诊断。
- 对照 ordinary、stable_fixed、Block LSD 两种块长与 Rust stable；先解决与 MSD 的差距，其他参照帮助理解结构。

### 阶段 1：三个小而独立的实验

1. C + cached 两数组。
2. C + 路径/环归位。
3. 既有 hybrid + 准备好的根统计回退，gate 和 cache 条件不变。

三者分别回答元数据冗余、记录移动、重复准备的问题。这个顺序按试验成本与可归因性安排，不是已证明的性能收益排名。单项通过后才测相容组合。

### 阶段 2：证据驱动的分支

- 若元数据分配占比显著，做跨 cache 入口的有界复用。
- 独立比较无单调检查、旧独立扫描、融合 histogram 三版；保留末尾逆序。
- 空间账本核准后，单独试生命周期感知准入；记录整棵树的变化，不仅记录时间。
- 只有多层 cached scatter 占比足够，才实现 ping-pong。

### 验收

- 沿用四尺度、五布局、十分布，并在自然准入点和 dyadic 势边界前后补点。
- 同进程轮换、同输入地址、计时外恢复、完整身份与稳定性检查；workspace 分配释放在计时内。
- 报每尺度、每布局、每负例，不只报几何均值。±5% 是描述区间，不是显著性检验。
- heap 请求字节、stack、allocator overhead、RSS 分开，不把局部 scratch 当总峰值。
- 用符合契约的 extractor 检查正确性；用变化/异常 extractor 检查安全及 panic 行为，不承诺违反契约后的排序语义。
- 新 unsafe 路径独立回归、适用的 sanitizer、边界模型验证；不能继承旧实现“已通过”的标签。
- 若减少了工作却重复测量仍普遍变慢，应撤回或重新解释，不用越来越多分布特例补救。

## 12. 最终交付标准

一个可保留的改动，需要同时给出：正确性条件、空间生命周期、减少的工作、真实计时、未解决的负例、实现复杂度的代价。

本轮最值得争取的是让统一内核少做一部分确定的无用工作。数学证明负责说明哪些工作真的被删除，以及代价在哪里；跨尺度测量负责决定这些删除是否值得进入最终实现。
