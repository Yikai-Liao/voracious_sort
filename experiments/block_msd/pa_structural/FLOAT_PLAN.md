# Float/double performance extension

The user requested f32/f64 performance while the final integer matrix was running. This extension leaves its frozen algorithm, Cargo files and integer runner unchanged. A separate crate includes the existing runner to reuse method dispatch, timing boundaries, alternating rotations, allocator and full-record oracle. Its own source and lockfile must also be hashed in each frozen executable's metadata. No float compilation or timing overlaps the integer validation.

Four layouts: f32 (4 bytes), f64 (8), f32 plus identity/payload (16), and f64 plus identity/payload (32). Main finite inputs contain no signed zeros, NaNs or infinities, so numeric partial ordering and the repository's converted-key order agree. Cases: uniform [-1e6,1e6], the sum of twelve uniform samples centered at zero (`normal12`, an approximate normal), broad finite binary exponents (`log_scale`), 16 values, roughly 90% one value, 8 or 16 dispersed mantissa bits under a fixed positive exponent, mixed signs with 8 dispersed mantissa bits, nonzero subnormals, sorted uniform and reverse uniform.

Native primary matrix: 11 cases x 4 layouts x B64/B512 = 88 cells, n=1,048,576, seed42. Seven slots `[candidate, oldPA, Rollercoaster, BlockLSD, StableMSD, oldPA, candidate]`, 14 repetitions, 8,624 rows. Generic target screen: uniform, skew90, sparse8, sparse16 x four layouts x both blocks = 32 cells with the same slots and repetitions, 3,136 rows. A fresh seed20261022 target reversal covers sparse8/sparse16 x four layouts x both blocks, n=262,144, six slots and 12 reps, 1,152 rows. Keep ELF cohorts separate.

Special-value cohorts use `special_mix` and unrestricted raw IEEE bits. The mixture contains both signs of zero, infinity, quiet/signaling NaNs with distinct payloads, subnormals and finite values. These are sorted by the repository's existing converted-key contract, preserving every input bit and stable record identity. The public root documentation does not guarantee nonfinite-value behavior; Rollercoaster and StableMSD have partial-order comparison paths and are excluded from this cohort. Old PA, candidate and BlockLSD are compared in five slots `[candidate, oldPA, BlockLSD, oldPA, candidate]` over 10 repetitions: 16 cells and 800 rows per target. This does not extend public API guarantees.

Before timing: verify finite generation and order agreement; verify actual f32/f64 record sorting with NaN bits, identities, payload and ties. A separate native Work executable covers all four layouts' sparse8/sparse16/signed_sparse8 inputs at n65,537, B64; compare every Pa_packed / Pa_kernel Work field and leaf distribution. Instrumented wall times are not performance evidence.

Use the existing predeclared retention rules: candidate/oldPA median >1.05 and p10>1 is a material signal; inspect same-cell A/A and independently repeat signals or ambiguous >5% medians with reversed slot order. Do not change algorithm admission thresholds to select passing float inputs. Preserve failures and report special-value behavior separately from the finite comparison table.
