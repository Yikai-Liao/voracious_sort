# Bounded cached leaves and odd-block layout screen

The count-boundary/local-dense-LSD experiment was rejected at `4e88261`. Its new scheduler, full-key completion, methods and module are removed from active code; raw evidence and the rejected tag preserve them. This cohort starts again from the original `6fceaaa` kernel. It tests two independent changes and their explicit combination.

- `Pa_leaf_cached`: after fixed-label distribution, finish <=128-record children directly using a bounded cached-key sorter. Convert each key once, sort original u8 indices by (converted key, original position), then apply the resulting permutation by disjoint cycles. Two-record leaves keep the direct compare/swap. Key and index arrays have fixed capacity128, at most 2 KiB+128 bytes for native u128, plus one record temporary. There is no full-input key array. This preserves all distribution and logical Work counters.
- `Pa_odd_blocks`: use the largest odd block capacity no greater than requested B. B64/512 therefore mean actual capacities63/511 for this method. The same capacity is used for block allocation, directory geometry and dense-budget calculations; supplied B remains the upper workspace parameter. No padding, added record buffer or hardware discovery is introduced. Record scratch decreases; directory metadata can rise slightly, so memory peaks must be measured rather than claimed unchanged. The existing O(B + n/B) space family and release-before-recursion lifecycle remain intact.
- `Pa_odd_cached`: explicit combination. Both isolated methods remain in the same executable to attribute any observed gains or regressions.

Odd geometry tests the hypothesis that a power-of-two record-block stride contributes to the observed losses. Without hardware counters, timing alone will not establish cache-set conflicts as the cause. No block-size sweep or input-dependent admission rule is allowed in this screen. Converted-key/stability semantics, hardware token and packing selection are unchanged. Existing dense/local distribution branches are preserved; the rejected new local-dense scheduler is absent.

Correctness precedes timing: complete-record and every-length leaf tests, full native Work library suite, float finite-order and actual special-bit record tests, including all three new methods. First build only the native float executable. Freeze exact source/harness/plan/scripts and wait for all builds/tests to end.

First screen: eight finite cells (uniform/sparse16 x f32/f64/f32_id16/f64_id32), n1,048,576, B512, seed42, CPU2. Ten slots `[combined, original_PA, cached_leaf, odd_blocks, Pa_kernel, Rollercoaster, Block_LSD, Pa_kernel, original_PA, combined]` use 20 repetitions for a complete rotation in both directions. The two isolated ablations are causal controls over the rejected kernel, not separately accepted candidates. Combined/original-PA material signals use the predeclared >1.05 median and >1 p10 gate, same-method A/A and independent reversed 16-repetition four-slot confirmations. If combined fails, stop and record; no full-matrix claim. If combined passes, screen B64 counterparts and normal/subnormal scalar floats, then representative integers and generic ISA before broader acceptance.

Full acceptance, if justified by small screens, still requires current-source original103 integer cells, the finite/special float cohorts, ordinary-ISA screens, fresh seeds, frozen-original ABBA, memory and separate Work. Existing source cohorts cannot satisfy these requirements for this new source.
