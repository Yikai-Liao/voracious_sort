# PA：结构性改进方向与数学推导

日期：2026-10-18（UTC+08）  
实现基线：`Yikai-Liao/voracious_sort`，`block-pa-unified`，`36a279bd0d6effaa16f70e77c3d5ac18d962b74b`。  
修订证据：`745cea6ab21030710cb036f88fa757505ef1990b`，新增同程序 Fa／Rollercoaster／LSD／Stable 对照；排序实现未因此改变。

## 本次修订：新对照改变了什么

新比较包含103个场景，每场景12轮，每轮6个槽位（候选两次，四个对照各一次），共7,416条计时记录。当前性能判断优先使用这一轮同 ELF 配对数据，旧轮数据保留用于机制与工作量分析，不能混合求均值。

| 对照 | 候选配对中位数更快 | 定位 |
|---|---:|---|
| Fa | 102/103 | 内部前沿实验对照，不是外部独立库 |
| Rollercoaster | 76/103 | 不稳定排序；允许等键换序 |
| 冻结 Block LSD | 91/103 | 稳定排序，稀疏宽键仍是主要负项 |
| Stable MSD | 100/103 | 稳定排序，三个中位数负项的波动范围均跨过持平 |

唯一 Fa 中位数负项约1.003，配对p10/p90约0.969/1.127。**没有证据支持为了这个近持平点优先加入 Pa/Fa 动态选择。**

新证据不只说明“反序输给 Rollercoaster”。它还显示均匀随机输入上的差距：

| 场景 | 候选 / 对照配对中位耗时 | 对照 |
|---|---:|---|
| 1M u128 sparse，B512 | 2.694 | Block LSD |
| 1M u32 uniform，B64 | 1.120 | Block LSD |
| 1M u64 uniform，B64 | 1.428 | Rollercoaster |
| 1M u64 uniform，B512 | 1.353 | Rollercoaster |
| 1M wide32 uniform，B64 | 1.178 | Rollercoaster |
| 1M wide32 uniform，B512 | 1.347 | Rollercoaster |
| 1M large128 uniform，B512 | 1.320 | Rollercoaster |
| 1M u16 reverse，B64 | 3.587 | Rollercoaster |

这些列出的配对比值p10均高于1，但p10/p90仍只是样本分位数，不是置信区间。

原先的12个未见种子前缀场景在这次比较中，中位数仍全部快于四个对照；它们现在是冻结候选的重复验证，不能再算一次新的独立留出集。新增证据是计时比较，没有新增 Fa／Rollercoaster 辅助堆测量，不能把旧空间结论扩展到它们。

实践和论文的比较证据因此增强；理论新颖性不会因增加比较对象而改变。后续仍需要独立实现的外部对照和硬件/编译器多样性。

因此计划调整为：

1. **稀疏坐标投影继续优先，但不能独占后续探索。**它无法解释普通均匀宽键的差距。
2. **密集随机键的物理执行调度升级为并行研究主线。**关注节点输入规模、桶缓冲工作集和重复归位，而不是继续寻找少量变化位。
3. **反序新增稳定性对齐的诊断前置项。**先分解原因，再决定是否修改生产路径。
4. **Fa 组合下调；条件子掩码保留为次级正交方向。**其价值取决于子区间内实际减少的变化量，不应假设均匀独立数据也会大幅获益。

### Rollercoaster 反序差距的解释边界

7416条记录通过各自适用的校验，说明计时结果有效；不代表比较双方承担相同语义成本。

源码中，百万条u16反序数据由随机u16键排序后反转得到，键域最多65,536，重复不可避免。Pa 的反序完成会反转整个范围，再修复等键组次序；Rollercoaster 的降序快路径允许直接反转而不修复等键顺序。原始u16值也没有可区分相等副本的身份字段。

所以新报告中的“差距不是稳定性约束造成”的归因尚未被隔离对照证实。不能据此断言全部差距来自稳定性，也不能排除稳定性成本。应增加：

- 相同反序键、带唯一ID/payload的记录。
- Rollercoaster 降序路径加等价稳定修复的控制版本。
- Pa 关闭修复的**仅诊断**版本，不能作为稳定算法候选。
- 更宽键域中的完整键全异反序输入，以及不同等键组长度。

分别测顺序检测、反转、等键修复，而不是把不稳定对照的总时间直接设为稳定实现必须达到的门槛。

## 0. 结论与范围

结构性研究保留三件事；新对照使第三件与第一件同为主线，第二件作为正交候选：

1. **用真正变化的位构造保序标签**，消除“信息很少、键位跨度很大”导致的无效递归。
2. **按分区后的条件变化掩码完成子区间**，避免把父区间的变化范围机械地继承给每个子区间。
3. **把逻辑分类与物理执行分开决策**，用散布、扫描、归位和标签计算的明确账本，选择继续分区还是直接完成。

这三条分别对应：表示、信息复用、执行调度。它们不是针对 `sparse`、`deep_unique90` 等测试名称派发的特判。

本报告是只读源码分析和数学推导，没有实现或测量新候选。下文明确区分正确性保证、逻辑工作量保证与待验证的速度收益。**没有任何一条可以直接保证所有平台、所有输入的实际耗时不退化。**

建议保留现有统一 PA 作为强基线，不重写 Block 后端，不把已经有效的 PrefixBand、有序检测和稳定叶子一起替换。

## 1. 已有证据：当前缺口是什么

旧轮矩阵（36a279bd）中，统一 PA 对 Stable MSD 有 101/103 个场景的配对中位数更快，对冻结 Block LSD 有 92/103 个更快。新轮计数已在文首更新，下面旧表用于说明结构性问题，不能替代新比较。这里的 LSD 是实验固定的 `d6f6b704`，不是未经核对的未来或其他分支版本。

最明显的四个负项均为百万条宽键稀疏输入：

| 类型 | B | PA / Block LSD 配对耗时比 |
|---|---:|---:|
| u128 | 64 | 1.306 |
| u128 | 512 | 2.533 |
| wide32 | 64 | 1.589 |
| wide32 | 512 | 2.105 |

这个生成器只让第 `0,18,36,54,72,90,108,126` 位变化，形成256种等频完整键。最高变化位很高，但总共只有8个变化位。

最终 B=64 工作量记录中，u128 与 wide32 的统一 PA 均为：

| 指标 | 数值 | 含义 |
|---|---:|---|
| 节点数 | 245 | 多次独立分类与分布 |
| prepare_records | 6,291,456 | 约6n次节点准备读取 |
| scatter_records | 8,388,608 | 8n次 radix 散布 |
| compact_records | 10,461,824 | 实际归位写入槽位，含约定的 padding 槽位 |
| runs_records | 5,242,880 | 约5n次子区间扫描 |
| max_depth | 5 | 最大递归深度 |
| max_path_passes | 8 | 一条路径最多8轮散布 |

这里的 `passes=250` 是各节点轮数之和，不能说成每条记录散布250遍。当前最终证据没有同一组 B=512 稀疏工作量，也没有可直接读取的 `L_frozen` 工作量计数，不能凭空补齐。

源码明确显示：冻结 LSD 在一个 Sorter 内处理所有变化字节，最后 compact 一次；PA 的多个宏节点各自完成分布和归位。因此，当前结构性问题是：**递归没有换来更少的有效字节散布，却增加了节点准备、边界扫描和归位。**这能解释额外工作，但尚不能把各部分直接换算成墙钟耗时占比。

## 2. 统一符号：不要混淆键宽、变化位数和熵

设当前节点有 m 条记录，转换后的保序整数键为 x，父节点允许处理的原键位范围为 `cap`。定义精确变化掩码：

```
V = (OR_i x_i) XOR (AND_i x_i)
V = V AND mask(cap)
```

它也等于 `OR_i(x_i XOR x_0)` 在该范围内的结果。现有完整准备扫描已经能够提供它。

定义：

- w：V 的最高置位位置加一，即当前代码的有效跨度。
- q：`popcount(V)`，真正发生变化的位数。
- a：V 中非零字节的数量。
- s：一条记录的字节数。
- B：每块容纳的记录数。
- R：每轮桶数，当前固定256。
- k(m)：当前 PA 的普通位预算，即 `8 × ceil(log_256 m)`，再受剩余宽度约束。

一般有 `q ≤ w`，但二者可能差得很远。当前反例为 `w=127、q=8、a=8`。

q 给出的只是不同键数量的上界：`distinct ≤ 2^q`。它不是实际不同键数量，也不是 Shannon 熵。比如两个互为按位取反的键可以让所有位都变化，但只有两种取值。不能因为采用 q，就声称算法已经“熵自适应”。

## 3. 第一优先级：变化位坐标上的保序分类

### 3.1 完整投影

把 V 的置位位置按从低到高排列：

```
p_0 < p_1 < ... < p_(q-1)
P_V(x) = Σ_j bit(x, p_j) × 2^j
```

它删除整个节点内恒定的位，保留所有变化位的相对高低顺序。

**保序证明。**对任意不同的两个键 x、y，设 h 是它们最高的不同位。h 必在 V 中。原键比较由 h 决定；投影后，h 对应的位仍高于其他所有不同位，所以比较结果不变。等键也投影为相同标签。因此，对完整投影标签做稳定排序，与对原键稳定排序完全等价。

这个证明针对转换后的保序键。signed/float 必须沿用既定转换及排序语义，不能直接对原始浮点位模式套用结论。

### 3.2 部分投影：统一替换普通前缀坐标

如果 q 超过本轮标签预算，只选择**最高的 k 个变化位**，按原相对顺序压缩。这样得到单调的区间标签：不同标签的先后顺序与原键一致；同标签组内继续排序。

不能随意选低位或“最容易提取”的位作为 MSD 分类，否则标签不再对应有序区间。

若最低被选中的原位位置为 p，递归的安全剩余范围为原坐标中的 `[0,p)`。也就是现有 `remaining/cap` 应保存 p，**不能把 q−k 当作原位坐标**。完整投影则直接标记 terminal。

### 3.3 为什么先测 q≤8

q≤8 时，完整投影落在一个字节，天然复用256桶后端，不需要 `2^q` 之外的更大桶表。这是现有基数的自然边界，不是针对某个键类型的经验阈值。

对上述稀疏输入，目标逻辑变化为：

```
原来：8轮有效字节散布 + 多个PA节点 + 多次归位
候选：1轮完整标签散布 + 一个终结节点
```

先限定“q≤8且a≥2”，可以避免给本来只有一个有效字节的情况增加压缩开销。保留有序检测和已经批准的 PrefixBand 优先级，再在普通回退路径使用这个判断。

这只是最小实验范围。更一般的方向是按最高变化位的数量预算标签，逐步研究9–16位、17–24位等情况，不能未经测量就全面替换现有前缀。

### 3.4 实现成本与风险

- 每节点预计算移位/掩码提取计划；不创建 O(m) 标签数组。
- 连续变化位段可合并为一项移位与掩码，避免逐位处理。
- 原生窄键路径保持原生宽度，避免为了统一接口把所有输入抬升为 u128。
- 不以 BMI2/PEXT 为正确性前提；硬件路径只能是额外实现，且须单独测量。
- 当前标签接口与原键类型关联，若想把完整8位标签真正落实为 u8 内核，需要检查接口与代码生成，不能假设编译器一定自动消除宽类型操作。

压缩8个离散 u128 位可能需要多条指令；标签在直方图、散布等位置可能被重复计算。一次256个活跃桶的散布，也可能比单轮只有两个活跃桶更不利于缓存。因此，“散布轮数减少8倍”不等于耗时减少8倍。

还有一个较便宜的中间方案：只拼接活跃的原字节，保留字节内部的位。它可以改变 PA 的前沿预算、跨过空字节，但已有后端本来就跳过不活跃字节，所以不能把这种方案宣传为天然减少了 LSD 的有效散布轮数。它适合用来判断逐位压缩是否过贵。

### 3.5 必须保留的诊断对照

先做一个不压缩标签的对照：根据低变化位数量，选择在当前节点以 Identity 完成原键的全部有效字节。它仍做8轮散布，但不再递归。

这个对照用来拆分两种收益：

1. 取消递归与多次归位的收益。
2. 压缩标签、减少散布轮数的额外净收益。

Identity 对完整键排序始终正确；低 q 只是选择它的成本启发式，不是其正确性条件，也不是速度保证。

## 4. 正交候选：子区间条件变化掩码

### 4.1 现有信息损失

`local_distribution` 可以先按最高活跃字节分区，再完成各子区间。当前实现把同一份父区间 `low_variation` 交给各子区间，所以父区间内发生变化的某字节，即使在某个子区间已经恒定，仍可能执行散布。

这不同于第一方向：第一方向压缩全节点的恒定位；本方向利用“给定高位桶之后，剩余位变得恒定”的条件信息。它适用于存在字段相关性、前缀相关性的数据，不只适用于全局低变化位数。

### 4.2 提案

在本来就要执行的高位桶精确计数扫描中，为每个桶同步维护标签的 OR 和 AND，得到该桶自己的剩余变化掩码 V_b。子区间完成时使用 V_b，而不是统一的父掩码。

如果该路径原本没有这轮扫描，不要为了“信息更完整”无条件新增扫描。先只接入已有计数路径，明确其触发范围；再判断扩大范围是否值得。

### 4.3 可以证明的散布工作量界

设父标签有 a 个活跃字节；先处理最高活跃字节，桶 b 有 m_b 条记录，其剩余活跃字节数为 a_b。

```
直接完整处理：W_full = m × a
分区后按条件掩码处理：W_split = m + Σ_b m_b × a_b
```

因为 `a_b ≤ a−1` 且 `Σ_b m_b=m`：

```
ΔW = W_full − W_split
   = Σ_b m_b × ((a−1) − a_b) ≥ 0
```

这是 radix 散布记录次数的保证，不含有序检测提前结束、比较叶子，也不包含额外掩码更新、边界扫描、直方图初始化和 compact。它不能直接升级成总时间单调改善。

### 4.4 空间与计数注意事项

- OR/AND 表新增约 `2R × sizeof(label)` 的状态，属于固定桶数下 O(1) 元数据，但必须计入实际预算，不能偷偷超出原先字节限制。
- 避免把这些表留在祖先递归帧中；信息消费完即释放。
- 各子区间现在可能消耗不同轮数，原来的“所有记录具有相同标签 pass 数”测试与统计必须修改。
- 分别记录总散布数与最大路径轮数，不能把各子区间 pass 数简单相加后当作一条路径的工作。

这个方向的优点是能产生可核对的精确 ΔW；缺点是每条记录多两次桶状态更新，宽标签的状态表也会消耗缓存。

## 5. 另一主线：以物理成本选择终结前沿

### 5.0 新对照要求增加的密集键诊断

普通均匀u64/u128键的q通常很大，第一方向不会直接解决其问题。要把“选择多少排序信息”与“怎样在内存中完成这些信息”分开。

现有 `local_distribution` 的重要门槛是 `512Bs ≤ 16 MiB` 时直接完成整个标签。它测量的是工作区预算，不是节点输入 `m·s` 的大小。以百万条u64、B64为例，节点输入约8 MiB，缓冲预算仅256 KiB，二者不是同一个工作集。

一个可检验的假设是：在大节点上，对整个标签连续完成若干轮，可能不如先分高字节、再在较小连续子区间中完成剩余字节。**目前没有硬件计数证明该差距由缓存导致，不能直接以“缓存优化”归因。**而且 large128/B512 已经可能进入局部完成路径，不能用同一个门槛解释全部随机负项。

先用相同稳定后端比较以下物理日程：

1. 当前日程。
2. 同一逻辑标签整体完成。
3. 同一标签先完成最高活跃字节，再完成各子区间剩余字节。

初始比较固定标签、变化掩码、桶数和B，隔离物理日程。记录散布、compact、边界扫描和真实分配；再加入第4节的条件掩码，避免一开始同时改变两个机制。

必须同时考虑输入/子区间字节量、活跃输出桶缓冲、目录元数据。不要简单把原有“缓冲预算门槛”换成另一个仅依据输入大小的门槛。对uniform数据，条件掩码可能几乎不减少低位散布，此时收益若存在，更可能来自执行局部性或调度成本，仍需测量验证。

已批准的 PrefixBand 与深偏斜逻辑继续保留。新日程应当在同一分类标签内试验，不要顺手改变多数前缀策略。

### 5.1 为什么仅改 k(m) 不够

`k(m)=8×ceil(log_256 m)` 隐含了“处理一定数量的键位，能有效减少子问题”的直觉。但实际减少程度取决于变化位位置、分布相关性和偏斜，而不是只有 m。

同样8轮散布，可以发生在一个宏节点里，也可以分散在245个节点里。两者的边界扫描、分配、compact 和标签计算成本不同。

因此目标不应只是“选择更好的位数公式”，而应是：**选择哪些有序区间在当前节点直接完成，哪些值得进一步细分。**

### 5.2 显式工作量模型

至少维护或离线分析以下量：

```
W = 总radix散布记录数
C = 总compact记录槽位写入数
Q = prepare、边界及其他扫描读取量
E = 标签提取/分类计算量
H = 直方图、游标等初始化工作量
A = 分配次数及分配字节量
```

一个用于实验比较的成本模型可以写为：

```
T_hat = α·Q + β·sW + γ·sC + δ·E + η·H + allocation_cost(A)
```

这不是普适机器定律。系数受 CPU、缓存与记录大小影响，不能用逐场景拟合把已知结果“解释正确”。模型应使用少量独立测量校准，并在未参与选择的数据上检验。

模型最初的价值是排除明显坏选择：如果一次细分既没有降低后续活跃位工作，也没有让工作集进入更便宜的执行区间，却必然增加扫描与归位，那么应优先尝试直接完成。

### 5.3 避免为决策付出过高成本

使用信息的顺序：

1. 现有完整扫描的 V、m、记录大小和剩余 cap。
2. 已经存在的精确桶计数、条件变化掩码。
3. 少量采样，只用于预测是否值得支付下一步分析成本。
4. 只有模型显示足够收益空间，才考虑新增完整分析扫描。

采样可以选错成本路径，但不能改变排序语义；用于删除键位、跳过散布的掩码必须来自精确证明。

不建议第一轮就增加多组硬编码阈值或复杂在线学习。先用前两方向建立能解释实测结果的简洁工作量对照。

## 6. 对现有理论保证的影响

### 6.1 正确性与稳定性

统一证明方式仍是：分类标签对键序单调；每轮标签分布稳定；只递归处理同标签的连续子区间；完整标签覆盖所有变化信息时终结。

完整投影保持比较与相等关系。部分投影必须取最高变化位。条件掩码只能删掉该子区间内已证实恒定的位。三者都能纳入上述证明，不需要针对某个测试分布重新定义排序。

### 6.2 递归进度

当前 UnifiedGroups 的一个重要性质是：批准的 PrefixBand 中间组消费更多高位；两侧虽然可能不缩短 cap，但其规模小于父节点一半，下一节点关闭 heavy 分支，必须先执行普通前缀划分。

新投影分类必须保留这个调度规则，并保证非终结普通分类至少消费一个字节数量的变化位，或在不足时直接终结。以原键宽为上界，原有 O(d) 级路径深度论证仍有延续空间，d 为固定原生键字节数。

这是一项需随实现正式整理的证明义务，不应只因测试通过就宣称已完成。若放宽为每次仅消费1个位，仍然终止，但常数和按字节表达的界限要重新计算。

尤其要把记录工作与 CPU 指令工作分开：若标签每次都用循环提取 k 个位，又在 ceil(k/8) 个散布轮次中重复计算，则每条记录可能支付 O(k·ceil(k/8)) 次提取操作。当前固定原生宽度下它是常数问题；推广到可增长键宽时，不能继续无条件宣称总 CPU 时间 O(nd)，更不能仅因投影就宣称整个算法达到 O(n·ceil(q/8))。

### 6.3 辅助空间

固定桶数和记录大小时，Block 后端的主要空间为：

```
S(n,B) = O(B + n/B)
```

当前实现的主要字节项约为 `512Bs + 9n/B`，另有桶状态和递归栈。父分布工作区在进入子节点前释放，是峰值不随递归叠加的重要条件。

- 固定 B=64/512：目录仍为 O(n)，不能声称严格 O(√n)。
- B 与 √n 同阶：固定记录大小、桶数下可保持 O(√n)。
- 上述投影计划和每桶掩码为有界元数据，不引入 O(n) 的逐记录标签缓存。

若独立研究块长，最小化近似模型 `512Bs+9n/B` 得到 `B≈sqrt(9n/(512s))`。这是辅助字节数的平衡点，不是最快 B；不能把最省空间参数当作最优性能参数。

## 7. 修订后的最小探索顺序

先增加两个诊断前置项，再分开推进结构改进：

- **D0：反序语义对齐。**完成文首的稳定修复/全异键控制，确定大差距是否还有可移除的扫描或搬运。
- **D1：密集键日程对照。**按5.0节，在同一稳定后端、同一标签上比较整体与局部完成。这与下面A/B并行优先，不必等待稀疏投影完成。

| 顺序 | 候选 | 核心问题 | 第一轮保持不动的部分 |
|---|---|---|---|
| A | 低变化位节点直接 Identity 完成 | 取消递归本身能收回多少成本？ | 原键字节散布、Block内核 |
| B | q≤8、跨多个字节的完整投影 | 一轮标签分布能否抵消提取与多桶代价？ | 有序/PrefixBand优先级、工作区 |
| C | 已有高位计数路径增加条件掩码 | 精确减少的散布能否覆盖掩码更新？ | 分类规则与其余路径；D1先不带此变化 |
| D | 组合 B 与 C，再推广最高k变化位 | 表示与条件信息能否共同减少工作？ | 已验证的安全边界 |
| E | 用账本改进终结前沿选择 | 能否用少量规则替代粗略位跨度预算？ | 不引入逐分布派发 |

每项先单独比较，组合收益必须实测，不能把独立百分比相加。

不追逐Fa唯一约0.3%的近持平点。反序现在有独立诊断优先级，但只有稳定性对齐后仍然存在的可避免成本，才进入优化阶段；不能靠变化位投影顺带解决它。

## 8. 验收：能证明什么，必须测什么

### 必须证明

- 完整/部分投影的保序性、相等关系与正确剩余 cap。
- 精确掩码覆盖全部变化位，常量位删除合法。
- 稳定性、终止性、无额外线性标签数组、峰值工作区生命周期。
- 位数0/1/8/9/16/64/128及最高位移边界安全。
- 不改变现有 key 转换语义；不扩大尚未完成的泛型与异常安全承诺。

### 必须测量

- 同程序比较的103个场景，保留Pa A/A、Fa、Rollercoaster、冻结LSD和Stable；尤其宽稀疏、密集随机、反序与深前缀。新结果不与旧ELF计时合并。
- 变化位数7/8/9，位段连续或离散，低位/高位/跨64位边界。
- 相同变化掩码下不同频率分布，防止把低q误当均匀分布或低熵。
- 固定同一份逻辑键与身份顺序，仅把变化位嵌入不同原位位置：连续、隔字节、跨64位。投影后的排序标签应相同；借此把信息结构、位跨度和提取成本分开，而不是只复测当前8个固定位置。
- 高位与低位强相关、完全独立两类输入，检验条件掩码的收益与最坏额外成本。
- B、规模、记录大小边界；至少增加另一种机器验证可迁移性。
- 标签提取次数/成本、W/C/Q、分配、辅助堆，和最终端到端排序耗时分开报告。
- 所有稳定算法继续使用稳定key/ID/payload oracle；Rollercoaster的不稳定语义单独列出。新增反序稳定修复控制也须通过稳定oracle，原生primitive重复值不能独自证明等键身份稳定性。

延续冻结输入、原版/候选配对轮换、A/A、完整稳定 key/ID/payload oracle。正式计时不得混入计数器或并发构建。新数据必须保留负结果。

**保留标准：**结构性工作量确实按预期改变，目标负项有可重复净收益，原有强项没有可重复的实质退化，且空间/语义边界成立。性能门槛应在实验前结合 A/A 噪声冻结；不能事后移动门槛。逻辑路径未触发也不等于机器码布局绝不会影响其耗时。

## 9. 暂不优先的方向

- 任意选择多个排序器的外部派发：可能有效，但不能解释统一 PA 的内部缺口。
- 全量逐记录压缩键缓存：会引入 O(n) 附加数组，破坏当前空间主张。
- 直接在未 compact 的块视图上递归：理论上可能减少搬运，但会改变子区间连续性、块所有权、祖先元数据寿命和稳定复用证明。属于后端重构研究，不应和本轮表示改进绑在一起。
- 只调16 MiB gate或增加更多展开：可能有工程收益，但无法解决“127位跨度只有8位信息”的根因。

## 10. 最终判断

最值得推进的是把 PA 从“连续原键位上的前缀预算”，逐步改成“精确变化信息上的保序标签预算”，同时把子区间已经确定的信息保留下来，减少重复散布。

稀疏路线先用 A 拆出递归开销，再用 B 验证标签压缩；与此同时，D1直接研究密集键上的物理日程。C 是相对独立的、适用不同相关性结构的方向。D0只负责先识别反序中的稳定性成本。只有这些账本和实测吻合后，再抽象成统一终结前沿模型。

这条路线保留既有成果，改变的是决定工作量的表示与调度原则。它有比继续堆常数优化更强的泛化潜力，但该潜力仍须用独立实验兑现。
