# 投影必须分别约束标签宽度与分区粒度

原始普通前缀的位数预算由节点规模决定，但其中有些坐标可能在整节点内恒定。首版广义投影选择预算数目的最高变化位，压缩后又消费了更低的位。这同时改变了物理字节轮数和逻辑 fanout，不能只用轮数预测收益。

large128/deep_unique90/B512 的完整矩阵和独立复测证实大幅回退。其大部分记录原本在较大的前缀 run 中继续由radix完成；首版把 run 切细后，进入 stable leaf 的记录/节点急增。对应源码与失败证据在78c7307，不能因整体83/103胜过Rollercoaster而验收。

修正后，令 V 为精确变化掩码，w 为最高变化位宽，b 为原节点的位数预算，P 为 V 在最高 min(w,b) 个原始坐标内的子掩码。

- 若完整投影可表达（popcount(V) ≤ min(b,32)），还必须有 ceil(popcount(V)/8) ≤ P 的活跃字节数。否则旧根节点后续若遇到有序子段，可完全不搬动后缀，额外字节轮数会成为纯成本。
- 部分投影直接选 P，且只在 ceil(popcount(P)/8) 严格小于 P 的活跃原字节数时准入。不把“省掉的空洞”换成更多低位。若 P 超过32位则保留原路。
- 完整标签相同意味着完整键相同（祖先 cap 以上保持常量）；部分标签相同当且仅当旧前缀相同。两者都保持标签次序；部分节点的子区间、叶子大小和后续逻辑划分保持原状。

这给出的是分发工作量和分区不变量，不是所有机器上的性能定理。PEXT/可移植提取的成本、桶空间和代码生成仍需完整端到端验证。`Pa_packed_aggressive` 仅作同程序诊断，重现旧的过度细分；当前候选 `Pa_packed` 使用上述约束。

Classifier 的键类型与标签类型分离：原生转换键继续保留全宽；投影标签使用u8/u16/u32。标签变化掩码必须覆盖每个实际变化位，允许包含多余位。`remaining(key)` 必须在同标签内提供一致的原始坐标 cap；0 表示该标签内不再有未决键位。小标签可启用已有 reduced-radix workspace，这个选择由私有 `USE_COMPACT_RADIX` 表示。

Packed 提取计划固定大小、在独立分区调用帧内存在，没有逐记录标签或全输入缓冲。分发 scratch 在递归前释放，预算与16MiB缓存 gate 的意义不变。失败的普通标签缩窄与carried-boundary策略已从当前活动源码移除；源码和消融结果分别保留在5c5cc90和3a8dbc2。

当前独立debug-work计数验证（不作速度样本）：百万条large128/deep_unique90/B512，旧PA与修正版均为4,089,701条scatter、4,833个leaf、9,848条leaf记录；aggressive为3,145,728条scatter、65,840个leaf、944,582条leaf记录。由此可见，比旧版少23%的搬运仍能同时增加比较排序工作、导致36%的实际回退。另有专门的已按后缀有序输入回归，覆盖完整投影不得增加首节点pass的边界。
