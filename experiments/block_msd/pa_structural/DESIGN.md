# 投影必须分别约束标签宽度与分区粒度

原始普通前缀的位数预算由节点规模决定，但其中有些坐标可能在整节点内恒定。首版广义投影选择预算数目的最高变化位，压缩后又消费了更低的位。这同时改变了物理字节轮数和逻辑 fanout，不能只用轮数预测收益。

large128/deep_unique90/B512 的完整矩阵和独立复测证实大幅回退。其大部分记录原本在较大的前缀 run 中继续由radix完成；首版把 run 切细后，进入 stable leaf 的记录/节点急增。对应源码与失败证据在78c7307，不能因整体83/103胜过Rollercoaster而验收。

修正后，令 V 为精确变化掩码，w 为最高变化位宽，b 为原节点的位数预算，P 为 V 在最高 min(w,b) 个原始坐标内的子掩码。

- 若完整投影可表达（popcount(V) ≤ min(b,32)），还必须有 ceil(popcount(V)/8) ≤ P 的活跃字节数。否则旧根节点后续若遇到有序子段，可完全不搬动后缀，额外字节轮数会成为纯成本。
- 部分投影直接选 P，且只在 ceil(popcount(P)/8) 严格小于 P 的活跃原字节数时准入。不把“省掉的空洞”换成更多低位。若 P 超过32位则保留原路。
- 完整标签相同意味着完整键相同（祖先 cap 以上保持常量）；部分标签相同当且仅当旧前缀相同。两者都保持标签次序；部分节点的子区间、叶子大小和后续逻辑划分保持原状。

这给出的是分发工作量和分区不变量，不是所有机器上的性能定理。PEXT 成本、桶空间和代码生成仍需完整端到端验证。保留的 `Pa_kernel` 对照使用上述约束；`Pa_packed` 保留相同分类规则、未传递内核执行上下文的诊断版本，`Pa_packed_aggressive` 用来重现旧的过度细分。

压紧只在hakmem确认可用的硬件token下启用，无硬件时完整保留旧PA路径，不再使用软件压紧回退。当前库缺少架构无关的硬件提取能力查询，因此仅有一个薄适配模块引用其安全X86V3 token，其他目标返回None；CPU检测、指令调用和u128拼装均由库承担。

准入必须按旧Prefix实际右移后的标签计算活跃字节，而非原键字节边界。部分投影必须严格减少实际字节轮数；完整投影不得增加首节点轮数，且若完整变化已经被旧Prefix覆盖，同轮数的表示改写不准入。跨字节连续8位字段即属于后一种情况，旧标签可能已经只有一个活跃字节。硬件可用不等于所有输入都会提速；完整矩阵与独立复测仍是验收条件。

Classifier 的键类型与标签类型分离：原生转换键继续保留全宽；投影标签使用u8/u16/u32。标签变化掩码必须覆盖每个实际变化位，允许包含多余位。`remaining(key)` 必须在同标签内提供一致的原始坐标 cap；0 表示该标签内不再有未决键位。小标签可启用已有 reduced-radix workspace，这个选择由私有 `USE_COMPACT_RADIX` 表示。

Packed 保存固定大小的精确mask、标签宽度、原始递归cap和库指令集token，在独立分区调用帧内存在，没有逐记录标签或全输入缓冲。安全硬件token在分类循环外通过hakmem 0.2.0取得并传入Isa::run；压紧由库的Isa::pext提供。原本本地维护的BMI2 intrinsic、unsafe提取与软件压紧计划均已删除，仅保留库当前token API所需的薄目标适配边界。分发 scratch 在递归前释放，预算与16MiB缓存 gate 的意义不变。失败的普通标签缩窄与carried-boundary策略已从当前活动源码移除；源码和消融结果分别保留在5c5cc90和3a8dbc2。

`6fceaaa` 阶段的独立debug-work计数验证（不作速度样本）：百万条large128/deep_unique90/B512，旧PA与修正版均为4,089,701条scatter、4,833个leaf、9,848条leaf记录；aggressive为3,145,728条scatter、65,840个leaf、944,582条leaf记录。由此可见，比旧版少23%的搬运仍能同时增加比较排序工作、导致36%的实际回退。另有专门的已按后缀有序输入回归，覆盖完整投影不得增加首节点pass的边界。

## 分类器持有整个分类循环的执行上下文

仅在外层 `partition_packed` 调用 `Isa::run` 不足以保证普通编译目标的热循环内联 PEXT：独立编译的 scatter、dense 和 run-boundary 函数仍可能每条记录调用一次库的提取包装。native 全局编译标志会掩盖这项成本。普通目标的重复退化和原始汇编分别保存在 `VALIDATION_SINGLE_PATH.md` 与 `VALIDATION_KERNEL_FINAL.md`。

`Classifier::in_context` 把执行上下文作为分类器接口的一部分；普通分类器直接执行闭包。`Classified` 把记录转换与分类器连接起来，`Masked` 在规范化标签时继续转发上下文。全量变化扫描、精确直方图、分发和边界扫描在循环外进入上下文，之后直接分类记录。固定 64 条记录的成本采样仍沿普通调用路径，不影响其分类语义。子节点递归发生在该边界扫描的上下文调用返回后，scratch 仍在递归前释放；没有逐记录 token 检测或标签数组。

block scatter 的单条写操作使用局部宏，展开在同一上下文闭包内。此前的嵌套写闭包会被编译器单独提取，与普通目标实例共享函数体，使 u128 部分标签重新出现逐记录提取调用。`6fceaaa` 只把这项嵌套写展开，保留记录读取顺序、桶游标与块回收协议。这个修正必须同时验证普通目标和 native，不能用其中一个 ELF 的成绩替代另一个。

guarded-labeler 测试在 dense、普通 block、grouped block 和 Masked 规范化的实际分类点检查上下文已进入；单独的 Work 比较检查两种上下文策略的完整计数与叶长分布相等。`6fceaaa` 阶段冻结 generic ELF 的只读汇编检查覆盖 178 个相关上下文函数体，包括此前失败的 u32/u8 与 u128/u16 scatter，未发现直接提取包装调用。它只能证明已检查函数体的代码生成；端到端性能仍以各 ELF 的配对结果为准。

## 当前待验收候选：保守压紧与计数完成

浮点补测证明，少一轮全记录分发仍可能更慢。原失败样本的三个数字分别使用64/32/32个桶，压成两个数字后各使用256桶；这是实际输入的计数事实，不足以证明缓存冲突是原因。`Pa_strict` 在上述正确性约束之外，要求压紧至少省去两轮物理分发。完整标签与完整剩余原键的活跃字节数比较，部分标签与原前缀比较。该规则是更保守的经验准入，不是吞吐量定理，可能放弃原来有收益的单轮节省。

`Pa_counted_key` 从原 PA 出发，仅在普通非终端前缀比完整剩余键少至多一个活跃字节时，直接稳定完成整个剩余键。宽随机键继续走原比较叶子路径。已批准的 band、相等分类和原终端路径先于这项选择。`Pa_strict_counted` 组合两项机制，筛选时同时测量两个独立分量。

新模块 `counted_completion` 持有一次完整完成操作。预算内使用已有 dense LSD；预算外用现有 recycled-block sorter 稳定分发最高活跃字节。`step_with_lengths` 在原 pass 完成后读取已有的末块目录：每桶长度为完整块数乘块容量，再加末块有效长度。该接口不改变 scatter/fixup/compact，也不增加分类或直方图扫描。按桶序累加这些精确长度即可得到连续子区间；先 compact 并释放父 workspace，再递归完成较低字节。每一层都减少最高活跃字节，最多16层。

键中未变化的位在当前节点内保持常量。全键 Identity 标签可以包含这些常量位，它们不影响活跃字节的稳定排序；每次稳定分发保留同数字记录的原顺序，较低字节仅在已分好的高字节子段内继续排序，因此完整转换键顺序和等键稳定性均保留。每个桶的精确长度在 compact 前读取，compact 只改变存储位置，不改变桶顺序或长度。

记录加 dense 直方图仍受 `512 * B * sizeof(T)` 预算约束；block 的目录与 scratch 保持既有边界。父 scratch 不跨递归存活。每层增加256个usize计数，在64位机器上为2KiB，最多32KiB调用栈状态；这与堆分配预算分别报告。没有逐记录键或标签 sidecar。实际峰值分配仍需独立测量。当前正确性与小规模筛选见 [COUNTED_VALIDATION.md](COUNTED_VALIDATION.md)，通过之前不把新策略视为已接受优化。

## 集合多数的独立实验（未保留，历史设计）

变化坐标无法表达各位之间的相关性。小型有序键集合把旧“单键多数”推广为“集合多数”：64个等距样本形成最多8或32个候选键，完整覆盖扫描必须证实命中记录严格超过一半。排序后的代表键分别得到奇数标签，键间的间隙得到偶数标签；标签单调且精确命中只包含同一个完整转换键。命中区间直接结束，未命中区间继续使用原 cap。未命中记录总量小于父节点一半，因此即使 cap 不下降也不会出现不收缩递归。样本的频率与覆盖门槛只决定是否尝试，不参与正确性证明。

指纹表只是加速查找：预先选择可区分所有候选键的连续8位窗口，以256项表返回候选下标，再核对完整键。未见键的指纹冲突不能成为命中；找不到可分离窗口则回退。二分查找版具有同样分类/终止语义，用于隔离查找成本。每节点只有常量大小的字典与表，放在独立调用帧；原分发 scratch 仍在子节点递归前释放。父节点的集合计划在其间隙递归期间保持有效，因此额外调用栈状态为 O(log n)，不把这一部分说成 O(1) 总空间。

集合仅在 root/heavy 机会、原宽度超出普通前缀预算、无已批准 PrefixBand 时尝试；已有完整一字节投影优先。覆盖失败前不改变输入。8与32容量、指纹与二分版本分别计时，只有通过独立筛选才保留。
