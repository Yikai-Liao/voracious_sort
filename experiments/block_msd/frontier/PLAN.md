# Block MSD / LSD 单线程优化方案：结合 RadSort 论文后的修订

日期：2026-10-16  
研究基线：`Yikai-Liao/voracious_sort`，`block-msd-research`，提交 `34080cf0fb95355411e029046e026b5aa65fb68c`。  
范围：稳定排序、单线程、低辅助空间；暂不涉及线程调度、并行桶分配和 NUMA。  
状态：设计与实验计划。本文没有新增原生性能数据，没有修改或推送仓库代码。

## 1. 结论：调整验证结构，不推翻之前的数学成果

**保留“用固定小基数 Block LSD 排有序区间编号”的核心候选，同时补上论文式混合排序与简单前缀分桶这两个必要对照。**

论文已有“高位分桶后，在桶内 LSD 排完剩余位”的建议。因此，混合 MSD 和 LSD 本身不能作为新贡献。但论文的这一建议不等于我们提出的“可变深度前缀区间编码、一次处理长路径出口、只递归未解决区间”。后者的正确性推导、空间实现条件、工作量上界和已发现的负例仍然有效。

这次修订主要修正三点：

1. **区分两种收益**：把排序搬进缓存，与减少需要处理的 digit，是不同的机制，必须分别验证。
2. **补齐简单对照**：先确认直接前缀分桶的收益，避免把已有混合排序的收益归到复杂编号机制上。
3. **避免过早选定唯一默认路线**：缓存内不必继续使用分块内核，也不应一律 LSD 排完宽 key 的全部后缀；实验阶段先拆开比较，不立即写一个庞大的自适应调度器。

原候选没有因为论文存在混合路线而被否定。它需要回答一个更精确的问题：**在相同分布后端、稳定性要求和内存预算下，长路径编号带来的少搬运，能否覆盖选择代表 key 和计算编号的成本？**

## 2. 已有数据限定了我们要解决的问题

[34080cf 实验报告](https://github.com/Yikai-Liao/voracious_sort/blob/34080cf0fb95355411e029046e026b5aa65fb68c/experiments/block_msd/work_reduction/REPORT.md)记录的百万随机 u32 结果：

| 实现 | 耗时 |
|---|---:|
| local_free | 10.519 ms |
| A+B2 | 9.591 ms |
| 正确稳定 MSD | 8.370 ms |
| Block LSD，B=64 | 4.348 ms |
| Block LSD，B=512 | 3.360 ms |

这些是既有报告数据，不是本文重测。

已有优化已经显著减少归位写入，但仍然存在大量小叶子和递归管理。深偏斜输入还存在同一大群记录反复参与 variation、计数和 scatter 的问题。因此只减少一个数组、一次检查或某一类 copyback，未必足以消除差距。

必须同时避免两个误判：

- 少了归位写入，不代表整体就会接近 Block LSD。
- 引入混合排序，也不代表它必然比纯 Block LSD 更快。

尤其要区分 `wide32` 的 128-bit key / 32-byte record，与 `large128` 的 32-bit key / 128-byte record。key 宽度决定潜在轮数；record 大小决定搬运成本。

## 3. 论文提供的依据与边界

[RadSort 论文](https://arxiv.org/html/2607.05302v1)中与本方案直接相关的是：

- **§4.3**：除逐轮并行 LSD 外，还建议先按最高位分桶，再在桶内 LSD 排剩余位，改善工作集局部性。
- **§5.2**：小数组可优先普通 out-of-place LSD，并复用分块算法已有的临时空间。
- **§4.1**：允许消费者按逻辑块顺序读取结果时，可以不做最终物理归位。
- **§7**：递归 MSD 的 partial blocks 会累积；密实存放尾部可以控制空间，但论文没有进一步完成这条路线。

由此不能推出：高位分桶一定更快、桶一进缓存就应该排完所有后缀、或省掉最终归位就自动解决了递归所有权与尾块问题。这些仍需独立分析和实现验证。

## 4. 保留哪些成果，调整哪些判断

| 之前的成果或设计 | 当前处理 | 理由 |
|---|---|---|
| 逻辑区间数量与每轮物理桶数解耦 | 保留为核心 | 多个 label 字节可用固定 256 桶依次排序，不必给每个逻辑区间配缓冲 |
| 连续高位前缀的短 LSD 分桶 | 保留并单独测量 | 是最简单的结构对照，也是其他候选的组成部分 |
| 宽前缀＋代表 key 长路径出口编号 | 保留为重要候选 | 同时处理宽分叉和深路径；区别于单次最高位分桶 |
| 编号有序性、稳定性与递归进展证明 | 保留 | 是否已有相关论文不影响这些性质 |
| Boyer–Moore 与按位多数的区别 | 保留且突出 | 前者不继承后者的桶大小减半保证 |
| 以节点规模选择 label 字节数的规则 | 降为待比较参数规则 | 它偏向减少冲突记录，不等于缓存最优 |
| 每个宏节点最后 compact 一次 | 保留为最小实现 | 有成本，但降低第一轮实现风险 |
| 全局 Stream / Writer 改造 | 暂不与主实验叠加 | 防止同时更改分类、布局和所有权，难以归因 |
| 缓存内一律完整后缀 LSD | 不采用为统一默认 | 对宽 key 可能做大量不必要的 pass |
| 复杂编号必然优于简单混合 | 不作此结论 | 当前没有 native 数据支持 |

“先实现简单对照”是实验顺序，不是对复杂候选的否定结论。若已有代码可以直接复用，也不应为了形式上的顺序重写它。

## 5. 统一问题分解：分什么、怎么分、何时结束

将设计拆成三个问题，但不据此新造大量运行时 trait、Engine 或转发层。

### 5.1 逻辑划分

候选只有两类：

- **直接前缀**：取尚未解决的最高 k 位，编号就是这个前缀。
- **可变深度前沿**：普通区域按 k 位前缀划分；与代表 key 同前缀的区域，再按与它的最高不同位划分，另有完整相等组。

两者都必须划分出有序、互不相交的 key 区间。

### 5.2 物理执行

对所选区间编号进行稳定 LSD 分布。编号可以现场计算，不要求为 n 条记录保存标签数组。

- 大工作集复用已有 Block LSD。
- 在总工作集确实足够小且空间预算允许时，比较复用 scratch 的普通稳定 LSD。
- 同一次宏节点内完成所选 label 字节后，再处理下一层；不要每个 label 字节都额外完整归位。

### 5.3 终结

- 空区间、单例、完整 key 全等：结束。
- 已由完整 key 顺序检查确认有序：结束。
- 足够小的区间：使用既有正确的稳定叶子。
- 余下变化 digit 很少：完整后缀 LSD 是候选。
- 余下 key 很宽或区间仍大：继续前缀划分是候选。

“label 已排序”只能结束本轮分桶，不能据此认定桶内完整 key 已排序。

## 6. 两种收益的数学账本

### 6.1 缓存分解并不自动减少 scatter

设完整 key 有 D 个要处理的字节，顶层先处理 q 个高位，桶大小为 m_i，桶内再处理剩余 D−q 个字节。不考虑局部恒定位跳过时：

\[
q n + \sum_i (D-q)m_i = Dn.
\]

总 scatter 记录数与完整 LSD 相同。它能赢的原因只能来自更便宜的局部访问等因素，同时必须抵消分区边界扫描、初始化和额外归位。

例如 1,048,576 条 8-byte record，均匀按最高字节划分，平均 4,096 条/桶，即 32 KiB 输入；普通 out-of-place LSD 的输入加同等 scratch 约 64 KiB，另计计数表和其他活跃状态。这只是均匀分布下的工作集示例，不保证所有桶都小，也不保证某台 CPU 上必然驻留某一级缓存。

### 6.2 提前结束才可能减少所需 digit

若只解决高位前缀，单例直接结束，其余区间才继续，记录参与的轮数取决于分叉深度。

均匀独立分配到 Q 个前缀类时，仍位于非单例类的记录期望为：

\[
n\left[1-\left(1-\frac1Q\right)^{n-1}\right].
\]

百万条处理 24-bit 直接前缀后，约 6.06% 的记录仍在非单例组；23-bit 约为 11.75%。它们不是耗时比例，也不代表叶子调用数同比例减少。

这说明之前“更宽前缀”有真实的算法动机，不能仅因一字节分桶可能进缓存就否定。但额外全局 pass 是否值得，取决于它替代的局部排序成本。

### 6.3 深偏斜不是简单缓存分区自动解决的

如果几乎所有记录仍进入同一重桶，单次最高位分桶没有明显缩小工作集。继续逐层分桶可能重复搬运；直接完整后缀 LSD 则可能支付很多字节轮数。

长路径编号的价值恰在这里：它尝试把一条路径上的多个出口归入一次宏节点处理。若代表 key 选得合适，主要等值群可以直接终结。

代价是准备候选、编号提取以及 label pass。每个宏节点可以有多次 label scatter，不能称为“一次搬运”。没有完整多数 key 的重前缀、多重群、稀疏变化位仍是重要反例。

### 6.4 应比较总成本，不只比较单项计数

对一个宏节点 v，可用如下账本组织测量：

\[
T_v = T_{prepare}+T_{classify/count}+T_{scatter}+T_{fixup}
      +T_{compact}+T_{runs}+T_{leaf/children}.
\]

这不是可以凭理论填出系数的预测模型。不同存储层次、不同 record 大小和内核会改变每项单位成本。

插桩运行用于工作量解释；未插桩运行用于时间结论。两者不能混成一个精确阶段占比。

## 7. 修订后的最小串行架构

### 7.1 宏节点生命周期

1. 在现有入口保留正确的空输入、全等、有序和小数组终结。
2. 确定当前尚未解决的有效位范围。
3. 固定本轮 classifier：直接前缀，或可变深度前沿。
4. 用已有分布后端稳定排序所选 label 字节。
5. 宏节点结束时 compact 一次，恢复普通连续切片。
6. 归还/复用该分布工作区；扫描相同 label 的连续区间。
7. 对未解决区间逐个完成排序；单线程复用同一有界 scratch。

初版不将稀疏块链连同一整套 scratch 挂在递归栈上。允许保留少量祖先分类上下文和区间游标，但必须计入峰值。

### 7.2 分桶深度不能直接沿用一个未经验证的默认值

原先按 log256(m) 选择字节数，目的是让逻辑前缀容量接近记录数量，减少冲突。缓存分解则希望让子桶的总工作集下降到有效容量以内。两个目标可能得到不同深度。

第一轮只离线比较少量明确配置，例如直接前缀的一、二、三个字节；key 不足时截断。不要从均匀输入平均桶大小推导出偏斜输入也适用的保证。

对前沿候选，保留原先的规则作为独立实验配置。不要为了表面相同而把其 23-bit 粗前缀与直接 24-bit 前缀称为完全相同划分。

### 7.3 缓存内收尾的顺序

先固定既有稳定叶子与终结策略，对比 classifier；随后再独立测试普通 LSD 收尾。

这样避免出现“前沿变快了”，实际却是换了小数组内核的归因错误。宽 key 的后缀 LSD 回退要作为正式结果保留，不靠不断增加特殊阈值掩盖。

## 8. 空间预算与稳定性约束

### 8.1 空间

节点局部 Block LSD 沿用 O(σB) 个记录缓冲及 O(m/B) 目录，σ=256；常数按真实实现计。固定 B 时，目录随 m 线性增长，不能把固定 B 配置宣传为严格 O(√n)。

普通 LSD 的 scratch 必须来自同一个有上限的预算。若两个工作区重叠存活，计其总量；不能只报告某一个数组。实现复用未初始化存储时，需单独审查布局、对齐、初始化、析构与别名条件。

可将缓存内 scratch 上限 S 固定为实验预算，只有区间能被该预算安全处理时才使用；不要把每个桶的容量同时累加分配。祖先上下文、目录、计数表、输出和 allocator 保留量分别说明。

### 8.2 归位成本

每个宏节点 compact 一次仍可能产生多层成本。沿用旧实现上界时，节点 m 的额外记录槽位写入最多约 2m，另计初始尾部复制；整个排序应累计各节点，不能写成“总共只归位 n 条”。

先测实际 Σm_v、compact 字节和尾部搬运，再决定是否值得引入全局逻辑块流。论文允许跳过 finalise 的消费者接口，不会自动给普通数组排序提供零成本递归。

### 8.3 稳定性

- 高位或 label 分布必须稳定。
- 同 label 的后续排序仍须稳定。
- 相等完整 key 始终在同一组内，身份顺序保持。
- 降序捷径不能反转等 key 的相对次序。
- signed/float 统一遵守现有保序 key 转换和等值约定。
- label 的恒定字节与有序检查针对 label；不能误用原 key 的位掩码。
- 公式使用数学整数；native 实现须单独处理零宽、完整 128-bit key、移位等于类型位宽和掩码溢出。F 是区间数量，最大编号是 F−1；不要在 u128 中构造 2^128，完整宽度分支可直接使用转换后的 key。
- 对自定义 key 提取器的重复调用成本、异常和副作用契约单独处理。

## 9. 对照设计：四条路线，各自回答一个问题

这些是实验标识，不要求成为四套生产算法或四个公开 API。

| 标识 | 路线 | 回答的问题 |
|---|---|---|
| L | 完整 Block LSD | 当前真正要挑战的简单低空间基线 |
| H | 直接高位分桶，桶内 LSD 排完余下有效字节 | 论文式缓存分解是否值得；宽 key 是否退化 |
| P | 直接高位短前缀分桶，仅继续未解决区间，沿用稳定叶子 | 选择性前缀细分是否减少总工作 |
| F | 可变深度前沿编号，使用与 P 相同物理后端及叶子 | 长路径编号本身的增益是否覆盖额外成本 |

另外保留正确稳定 MSD 和现有最佳 Block MSD 实现作参考。原生普通排序也可保留，但标明稳定性和内存使用，不将不同约束混为同一个公平组。

F 与 P 至少做两种匹配：

- **相同 label 字节预算**：比较同样最多 t 个物理 pass 下的整体设计。粗前缀覆盖不同，这是设计本身的代价。
- **相同粗前缀深度**：检查插入长路径出口后的额外 label 宽度、准备成本与收益。若需多一个字节，真实计入，不能隐去。

F 选 p 的初版规则保持明确。Boyer–Moore、按位多数或采样不是可以混着报的同一算法。按位多数可作为理论参考或单独昂贵对照，不直接变成默认后端。

## 10. 实验顺序与停止条件

### 阶段 A：锁定基线与测量口径

- 固定提交、编译器、flags、CPU、亲和性、记录类型、key 分布与种子。
- 确认稳定 MSD 的等 key 身份校验正确。
- 同一进程、相同输入地址轮换比较；恢复输入和完整校验移出排序计时。
- 排序内部必要的 workspace 获取不得无说明移出计时。若另做复用 workspace 接口，所有候选用一致口径并单列结果。
- 固定峰值辅助空间预算，另报告各自最佳配置，不能混合两类结论。

### 阶段 B：先建立 P，保留 F 的实现接口

- 复用已有 Block LSD 完成直接前缀短排序。
- 宏节点只 compact 一次，复用现有稳定终结。
- 对 classifier 的必要改动保持局部，不额外造一层只有转发作用的框架。
- 记录前缀字节数、宏节点数、未解决记录数、叶子数和长度分布。

P 的结果是结构对照，不是 F 是否实现的唯一门槛：若 P 的失败正来自深偏斜，而 F 的作用正是减少深路径，就仍应在这些场景直接测试 F。

### 阶段 C：建立 H，单独确认缓存收益

- 相同顶层前缀分布，替换桶内完成方式。
- 确认输入与 scratch 的联合工作集，而非仅输入容量。
- 包含 u32 与 128-bit key，避免用窄 key 结论外推。
- 若 H 没减少 pass，却明显加速，结合硬件计数判断是否来自局部性；不能仅从时间反推具体缓存原因。

### 阶段 D：加入 F，检验原方案的特有价值

- 与 P 同后端、同叶子、同布局生命周期。
- 为 p 准备、label 提取、scatter、compact 分开记录工作量。
- 重点覆盖完整多数、只有多数前缀、多重群、长链与稀疏变化位。
- 不因均匀小 key 的局部劣势直接否定其宽 key/偏斜价值，也不因某个重偏斜大胜就宣布统一胜出。

### 阶段 E：最后才决定是否组合

如果某个简单选择条件能在未参与调参的数据上稳定区分收益与代价，可考虑组合。优先使用节点规模、record 大小、剩余变化字节数、已有计数等便宜信息。

若必须不断增加“某类型＋某分布＋某规模”补丁才能保住结果，则暂停组合，保留独立实验结论。此时需要重新考虑结构，不继续用阈值修补。

## 11. 最低测试矩阵

### 数据类型

- u32 key＋小 payload；u64 key。
- 128-bit key＋中等 record。
- 窄 key＋大 payload。
- 相同 key 分布下改变 payload 大小，以拆开提取与搬运成本。

### 规模

极小、叶子阈值两侧、cache 工作集边界两侧、百万及更大规模。覆盖 255/256/257、65,535/65,536/65,537 等字节数选择边界；不只挑二次幂。

### 分布

均匀、已排序、逆序、全等、少量 distinct、长公共高位、深偏斜链、多个重群、只有多数前缀没有完整多数 key、首元素离群、不同输入排列、内部稀疏变化位。

保留原先反例：128-bit key 在 0、18、36、54、72、90、108、126 位变化。原 label 规则在抽象 scatter 计数上已出现 6.25% 增加，不能删除或换掉这个案例。

### 正确性

每条记录附稳定身份 ID，与可信稳定排序逐项比较；检查 key 顺序、记录守恒和等 key 身份顺序。对前沿模型覆盖 label 边界、非零公共前缀、k<w、完整 key 终结，以及全部相同 label 但完整 key 不同的情况。

native 实现还需 release/debug、适用的 sanitizer、越界/未初始化/别名审查。数学模型通过不替代这些检查。

## 12. 需要记录什么，如何作出结论

未插桩：配对耗时分布、CPU 时间、峰值辅助空间、分配次数。充分重复并报告噪声和可复现回退，不将单次最好成绩作为结论。

插桩/单独诊断：

- variation / candidate / label 提取的记录访问数；
- 总 scatter 记录和字节数；
- 宏节点数、每条路径 digit 数、Σm_v；
- compact 与尾部搬运字节数；
- 初始化次数、区间扫描访问数；
- 叶子调用数、叶子记录总量与长度分布；
- 可用时的 cycles、instructions、cache miss、带宽指标。

判定原则：

1. 正确性和稳定性失败，直接淘汰该实现。
2. 辅助空间超预算，不进入等预算性能结论。
3. 更复杂的 F 必须展示相对 P 的可复现价值，并解释代价；否则不进入默认路径。
4. H 若主要改善窄 key 缓存局部性，就按这一边界报告，不声称解决宽 key 或偏斜。
5. P/F 若减少工作但仍更慢，保留数学结果，但承认实现或分类成本抵消收益。
6. 少数局部回退可以讨论取舍，但要公开范围、幅度和真实用途，不能由均值隐藏。
7. 若所有混合候选都不能超过 L，则保留 L；研究价值在于明确为何失败，不以堆特殊情况强行制造赢家。

## 13. 本轮不做的事

不做并行调度；不同时引入全局 Writer、动态大 radix、复杂采样器、跨类型 allocator、SIMD bit packing 或按分布命名的特化表。它们并非永远无价值，而是会让本轮无法回答“前缀结构与长路径编号到底有多少独立收益”。

不以“论文已有混合”否定前沿候选，也不以“数学证明正确”替代性能验证。

## 14. 给实现者的交付要求

- 固定基线与可复现命令。
- L/H/P/F 的配置和实际内存预算，不依赖口头说明。
- 正确性、稳定身份校验与所有负例。
- 原始计时数据与单独工作账本。
- 每一步只更改一个可归因的结构因素。
- 总结哪些收益来自缓存、哪些来自少做排序、哪些成本仍未解释。
- 明确哪些候选值得保留，哪些应停止；不要把未测试的未来改造写成完成。

**最终目标仍然是找到简洁统一的结构。简单对照帮助识别真实增益，原来的数学成果帮助我们提出和验证超出简单对照的机制；两者互补。**

# 附录 A：保留的前沿编号与工作量推导

以下保留上一轮报告的核心技术推导和已报告的模型结果，供实现者直接使用。它们没有在本次写作中重新运行。这里的“第一版”指 F 候选的最小实现，不表示整个修订计划必须先实现 F；原有 log256(m) 参数规则为实验候选，不是已证明最快的统一调度规则。

## 4. 一个编号，同时表示宽前缀和长路径

先去掉在整个当前节点中已证明相同的高位。令剩余有效 key 宽度为 w，选择 k 个最高位作为粗前缀，并选一个参考 key 位模式 p。下面编号公式中的 x、p 都指删去共同高位后的局部 key 值；原始记录中的 key 不改写。

1. 粗前缀与 p 不同的记录，按普通 k-bit 前缀分组。
2. 粗前缀与 p 相同的记录，按“与 p 的最高不同 bit”分组。
3. 与 p 完全相等的记录，单独一个终结组，不再排序。

每个分组仍是完整、连续的二进制前缀区间。第 2 步一次看到了整条路径上的出口，不需要每遇到一个出口就重新搬运仍在路径中的记录。

### 一个很小的例子

剩余 key 为 4 bit，粗前缀取前 2 bit，p=`0101`：

| key 区间 | 有序编号 | 仍需处理的低位 |
|---|---:|---:|
| `00xx` | 0 | 2 bit |
| `0100` | 1 | 已终结 |
| `0101` | 2 | 已终结，等于 p |
| `011x` | 3 | 1 bit |
| `10xx` | 4 | 2 bit |
| `11xx` | 5 | 2 bit |

现在只要稳定地排整数 0…5，就同时完成了粗前缀分桶和 p 路径上的多层分叉。编号相同不意味着完整 key 相同，所以只有标明终结的区间可以直接退出，其余继续递归。

### 编号的精确定义

令 \(\ell=w-k\)、\(h=p\gg\ell\)、\(a=x\gg\ell\)。p 的低 \(\ell\) 位记为 \(p_s\)，其中 1 的个数为 M。

- 若 \(a<h\)，编号为 a。
- 若 \(a>h\)，编号为 \(a+\ell\)。
- 若 \(a=h\)，使用 \(h+s(x)\)。

其中：

- x=p 时，\(s(x)=M\)。
- 否则，b 是 x 与 p 最高不同 bit 的位置（最低位为 0）。
- 若 \(p_b=1\)，\(s(x)=\operatorname{popcount}(p_s\gg(b+1))\)。
- 若 \(p_b=0\)，\(s(x)=b+1+\operatorname{popcount}(p_s\gg(b+1))\)。

这给出最多

\[
F=2^k+(w-k)
\]

个有序编号。可预计算至多 w 项的 b→s 映射，不需要 F 项表。普通前缀组留下 \(w-k\) bit；路径出口组留下 b bit；等于 p 的组已经终结。

### 正确性与稳定性

- **覆盖且唯一：**每个 key 要么处于其他粗前缀，要么具有唯一最高不同 bit，要么等于 p。
- **区间顺序：**首次不同 bit 决定大小，编号顺序与各前缀区间的顺序一致。
- **稳定性：**相等 key 的编号相同。稳定 LSD 保留它们的原始顺序，稳定递归继续保留该顺序。
- **递归进展：**每个未终结组至少消费 k 个有效 bit；没有“重新从原 key 顶部开始”而丢失进展的问题。
- 对 signed/float 必须使用现有的保序转换 key，不能直接对原浮点编码任意 XOR。NaN/等值语义继续遵守既有 key 契约。

## 5. 为什么要明确 p 的来源

“随手拿第一条”可以正确排序，但不能保证消除偏斜。构造每层先放两个少数派 key、最后放大量零，就能让每次 p 都落在错误分支，保留约 16n 次搬运。

### 第一版只用一个便宜的确定性规则

建议原型先用 **Boyer–Moore 的完整 key 多数候选**，融合进已有的 variation 扫描。如果某个完整 key 超过一半，它一定得到该 key；即使不存在多数，产生的任意固定 p 仍然保证排序正确，因此不需要为了正确性额外做验证 pass。[原始算法](https://www.cs.utexas.edu/~boyer/mjrty.pdf)

这样能确定性处理“多数记录等于同一个 key”的偏斜，而不引入大量 bit 计数。它**不保证多数前缀的代表性，也不保证所有继续递归的桶减半**：很多不同完整 key 共享一个前缀时，候选仍可能是离群值。必须专门保留这种负例。每条记录最多 ceil(W/7) 个 label pass 的界不依赖 p，仍然保留。

下面的按位多数只作为更强保证的理论参考，不在第一版同时添加第二条运行时策略。

### 可证明减半的参考版本

用于该理论版本的选择是：**p 的每一 bit 取当前全部 key 在该 bit 的多数值。** p 可以是不存在于输入中的合成位模式；不需要创造一条假记录。

对于每个非相等分组，存在一个**对整个组固定的 bit**，使组内所有 key 都在该 bit 上与 p 不同。普通粗前缀组取它的固定前缀与 p 的某个不同位；路径出口组取出口位。因此整个组包含在同一个少数集合中。于是：

\[
|\text{任意继续递归的组}|\le\lfloor m/2\rfloor.
\]

相等组直接结束。这是真正的分布无关进展保证，不依赖“当前数据恰好是零很多”。奇数 m 的多数条件必须写对，例如 \(\text{count}>\lfloor m/2\rfloor\)；偶数平票任取一边都保持该界。

### 多数计算不是免费的

可以用 bit-sliced 计数，在每个机器字里同时维护多个 bit 位置的二进制计数平面。计数第 i 平面的总访问次数不超过

\[
\min\left(m,\frac{wm}{2^i}\right),
\]

总计 \(O(m(1+\log w))\) 个 w-bit 平面操作，存储 \(O(w\log m)\) bit。对 128-bit key 通常需要多个机器字。可统计 `key XOR first_key` 再还原多数位，平票取参考位仍有效。

独立计数模型还发现一个不利例子：32,768 条记录中绝大多数同为全 1，若少量前导记录让各 bit 的计数相位错开，计数平面迭代从约 2.00 次/记录升至约 8.94 次/记录。不能用“重复 key 很多”断言这一准备必然便宜；这只是操作计数，不是 CPU 时间。

**这可能是整条方案最大的时间风险。** 均匀小 key 上，为获取强进展保证付出的指令，可能比删掉的工作还贵。这也是第一版不直接采用它的原因。不能把它藏成“一次普通扫描”。一个小随机样本可降低准备成本，但会失去确定性减半保证；暂不把多种选 pivot 策略做成一堆默认选项。

## 6. 用小基数 LSD 排大量逻辑编号

入口先处理 m≤A、零宽/全等、空输入等终结条件，再计算 t，避免零长度 log 或无意义分布。选 t 个字节容纳编号。对于本项目的 w≤128：

- 若 \(w\le8t\)，直接取 k=w，本轮编号就是完整有效 key。
- 否则取 \(k=8t-1\)。

此时 \(F\le256^t\)。例如 t=2 可以容纳 15-bit 粗前缀及其路径出口；t=3 可以容纳 23-bit 粗前缀及出口。

一个不按类型/分布列特化表的实验起点是：

\[
t=\min\left(\lceil w/8\rceil,\max(1,\lceil\log_{256}m\rceil)\right).
\]

该规则在百万深偏斜输入上也会选 t=3：一次宏节点仍有三次可能非恒定的 label-byte scatter，绝不是“一次搬运”。该规则使逻辑前缀容量与节点规模处于相近量级；它不是已证明最快的参数规则。随机百万输入取 t=3、k=23 时，普通粗前缀的非单例记录比例约 11.75%，不应拿基础版 24-bit 的 6.06% 冒充它的结果。这个 11.75% 是仍待处理的记录数量比例，不是叶子调用数；同一理想模型下仍约有 6 万个非单例区间，接近原来的 65,536 个叶子，只是多数变为很短的区间。

同一个固定本轮参数的编号函数用于所有 t 个 LSD pass。判断是否跳过某个恒定字节，必须看 **label 的字节**，不能使用原 key 的 variation mask：编号插入和位移会改变字节变化位置。若使用 dense count-first 后端，t 组 256 项边际直方图可以在一次扫描中取得，它们在 LSD 的中间排列后仍有效。第一版若复用现有大输入 Block LSD，则沿用完成块计数，不强制增加这 t 次逐记录计数；但它仍需正确处理 label 的有效位/变化信息。**不得在中途改变 p 或编号定义；也不得缓存每条记录的编号却仍声称没有线性标签数组。**

以下工作量假定保序 key 固定宽度、提取无额外分配且在本轮保持一致。自定义 extractor 的任意计算/分配，以及新 unsafe 实现的异常安全，都不由这些标量证明覆盖。

## 7. 工作量：可以证明什么

当本轮没有直接解决完整 key 时，消费的 bit 至少为 \(8t-1\ge7t\)。最后解决完整 key 的一轮满足 \(7t\le w+6\)。因此每条记录参加的小 radix 分布轮数之和满足：

\[
\sum t_i\le\lceil W/7\rceil.
\]

W 为初始有效宽度。W=128 时最多 19 轮；不能把“递归节点减半”误说成“总共只有 O(log n) 个 LSD pass”。比较叶子中的移动、最终输出和归位需另外计算。本修订采用节点局部 compact，其累计成本按主文第 8 节单独计入；此处不引入全局 Stream / Writer。

**仅对按位多数参考版本**，还可给出宏节点深度界，遇到长度阈值 A 即停止时：

\[
H\le\min\left(\lceil W/7\rceil,\lceil\log_2(n/A)\rceil\right)
\]

（n>A；提前等值终结只会减少深度）。第一版 Boyer–Moore 不继承这个 log 项，只使用不依赖 p 的深度界 ceil(W/7)。

原来 16 层重偏斜上的大群记录，可以通过一次宏节点内的少量 label-byte passes 直接到终结组。均匀输入则通过更多高位前缀减少未解决记录。这两者使用同一个有序编号和同一个物理分布内核，不需要“检测某个命名分布然后换算法”。

但时间仍包括：选 p 的准备（第一版为 Boyer–Moore 投票）、编号计算、所选后端的记录直方图或块计数、t 次 scatter、每个 pass 的桶设置、相同编号的区间扫描、叶子排序、最终输出与归位。**本证明是工作结构与上界，不是速度证明。**

## 8. 空间与所有权：不能省略的条件

### 8.1 第一版选最简单的节点局部实现

**先复用现有 Block LSD：在一个连续节点内排完所有选定的 label 字节，只 compact 一次，释放其工作区，然后扫描同编号区间并递归。** 不把未整理的稀疏块链挂在递归栈上。

这更接近原始 Block LSD 的简洁结构：本轮只有一个 Sorter，递归边界仍是普通切片。无需新增全局 Writer，也无需先实现新的共享尾块协议。Sorter's scatter 路径由完整记录 histogram 改成完成块计数的既有机制可以保留。

代价必须入账：每个宏节点大小 m，t 次分布之外，compact 最多再写约 2m 个记录大小的槽位，初始部分尾块另复制少于 B 条。若所有宏节点的记录数之和为 Σm_v，额外归位最多约 2Σm_v，而不是整个排序 O(n)。按位多数参考版本可用上述 H；第一版 Boyer–Moore 只保守使用 H≤ceil(W/7)，因此 Σm_v≤nH，不能套用减半得到的 log 界。一个宏节点即完成主要工作的输入，t=3 时约为不超过 5n 的分布/整理写入，加尾块和叶子工作。

释放工作区后才进入子节点，峰值沿用单次 Block LSD 的 O(256B) payload 缓冲与 O(n/B) 目录，再计祖先少量 p/映射、当前候选/投票状态及叶子 workspace；按位多数参考版本另计计数平面。**这个版本的峰值不能直接填写为旧 MSD 的 0.532 MiB；需要实测实际容量和常数。**

实现时必须把 classifier/context 贯穿 label variation、恒定字节判定、ordered 检查、内核分布与有效位宽，不能只替换 scatter 中一处 extract。内层“按 label 已有序”可以提前返回，外层仍需完成等 label 区间的剩余排序。

## 9. 上一轮已完成的模型验证和反例

上一轮研究没有运行仓库排序代码、没有 Rust benchmark、没有改分支。当时执行的是独立 Python/JavaScript 标量模型；它们使用普通集合容器，不证明 native 内存峰值或指针安全。

- 编号函数：W=8，所有 k=1…8、所有 p、所有 x，共 524,288 个映射检查，验证有序性、覆盖、前缀区间和剩余位数。
- 非平凡递归：16/128-bit 稀疏字母表、非零公共高位、顺序/逆序/周期/打乱/多数输入及 127/128/129、255/256/257 等长度边界，41,728 项检查通过。
- 独立复核另覆盖 149,796 个递归稳定身份比较，包含实际 k<W 的前沿和递归。
- 第一版选用的 Boyer–Moore 候选另通过 20,784 个宽 key 稳定身份检查；不把按位多数的减半性质套给它。
- 另外，按位多数参考版本的 8,000 组加权 key 分布检查了减半性质与每条路径的 pass 上界；权重允许覆盖大 m 的 t 边界，但不分配对应数量的真实记录。
- 初始 282,358 个小整数穷举虽然通过，但其有效宽度≤5，主要退化为完整 key LSD；**不把这个数字当作新前沿机制的有效覆盖证据**。
- 密集 byte-comb 和恶意首元素反例表明，首元素 pivot 可能仍有约 16n 搬运；多数 pivot 的抽象模型可在一个宏节点终结主要等值群。

还找到了直接的负例：128-bit key 仅在 0、18、36、54、72、90、108、126 位变化，256 个 key 等频组成 32,768 条记录。抽象普通逐-digit MSD 的 scatter 为 262,144 条；当前编号规则为 278,528 条，反而多 6.25%，尚未计入局部 compact。强减半版本也没有消掉这个差距。因此不能宣称新规则对任何输入都减少搬运；这必须作为下一轮淘汰/取舍依据，不能隐藏。

数学模型里的 `materialized_records` 是逻辑计数，不是原生真实写入总账。模型结果不能写成“已快多少倍”。
