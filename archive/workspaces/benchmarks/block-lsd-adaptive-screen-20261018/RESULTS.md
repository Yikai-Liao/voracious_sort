# Block LSD 改进评估结果

不采用本轮任何生产补丁，恢复原版。 两个局部前缀复用实现都造成了明确的浮点全相等退化；最后实现的 f32 中位耗时约为原版 1.98 倍、f64 约 1.24 倍，因此全部撤回。

单元素错位识别、固定两段归并草稿都已撤回。其余慢场景的通用方案需要新增有序段调度与空间受限的稳定归并，当前没有足够证据支持引入这套机制，见 [判断依据](ASSESSMENT.md)。不宣称修复 push-front、push-middle 或 organ-pipe。

原版始终保存在 `origin/archive/block-lsd-original-20261018`，commit `e649c6af49d6bfdde896ca40cad387235fce4bfa`。原工作区未修改；实验工作区和原始数据独立保留。

## 候选版本与拒绝依据

最初通过短筛查的前缀复用版本，在 109 条件确认中暴露了 f32 全相等慢 61.8%、f64 全相等慢 30.5%；两项六次配对均比同条件 A/A 完整对称包络更慢，因此拒绝。完整时间观测保留，内存测量在拒绝后停止，不算完成验收。该轮数据不能当作后续实现的成绩。

最后的局部尝试只把索引计算移到发现差异后的出口，根据迭代器剩余长度计算位置。没有新增类型分支、单元素识别或特定分布分支。其冻结版本为 `prefix-exit-index`。

## 验证与复现

最后版本覆盖 15 个条件，270 条时间观测和 135 条独立内存观测，全部通过 converted-key 稳定完整输出 oracle，包括 payload 与相等键顺序。两版的峰值请求堆内存全部相同，都通过原始 Block LSD 堆上界。所有进程正常退出且结束时 VmSwap=0。源码与数据摘要见 [verification.json](verification.json)，正确性测试见 [final-tests.log](final-tests.log)。

两版都使用 radix 8、相同 `max(1, floor(1024/s), ceil(4*sqrt(9*n/(512*s))))` 块长。每条件 3 seed 各作正反顺序，固定 CPU 2、单线程。整次排序、探测和排序内部的分配计时；输入复制、策略计算和完整 oracle 排除。逐观测热身，独立预复制输入，3 ms 目标批次和 64 MiB/2048 个输入缓冲上限；不代表冷缓存。计时与分配追踪是两个独立构建的程序。`block_before_aa` 调用与原版相同的函数。

源码、二进制摘要和调度在 [prefix-exit-index/manifest.json](prefix-exit-index/manifest.json)。历史候选各有独立目录与状态，不混合观测。重算最后的表格无需重跑排序：

```sh
python3 analyze_screen.py prefix-exit-index
python3 make_report.py
```

此前原版与其他算法的图、块长研究和数据归档保持不变。新主图按九种类型分面，不再把跨类型差异画成误差范围，见 [原版研究报告](../block-lsd-pr-20261018-story/REPORT.md)。
