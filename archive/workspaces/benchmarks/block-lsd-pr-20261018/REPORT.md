# Block LSD PR：时间与空间测量

候选 `e649c6af49d6`；上游 `3dbdd7f46006`。所有实现与二进制已冻结，测量保存在独立目录，PR 代码未改动。

完成 1,045 个输入条件，112,170 次时间观测、56,085 次内存观测。覆盖 9 种类型、23 种分布、主长度 128–1,048,576，另有 u64 均匀分布到 16,777,216 的增长测量。

时间覆盖整次排序及内部内存申请/释放，输入复制和 oracle 校验在计时之外。空间指标为排序期间额外存活的请求字节峰值，不含输入缓冲区和分配器内部元数据；进程 RSS 另列，包含 harness 和校验开销。

本次百万元素矩阵中，固定 512 元素策略相对原 LSD stable 的配对耗时比几何均值为 **0.798**（205/207 个语义一致条件），相对 TimSort 为 **0.361**。总体优势仍在，但结构化输入有大幅退化；较大记录也需要区分固定元素数与固定字节数。初始空间平衡 c=1 降低空间增长；扩大系数与字节归一化结果见下文补测，速度需结合具体参数判断。

## 补测：扩大系数与块字节归一化

初始 0.5/1/2 的系数窗口偏向空间最优点，未充分覆盖固定 512 两侧。初始公式将类型字节数放在根号内，也没有统一单块字节预算。按用户修正，完整保留初始结果，并单独冻结补测以下两类：

- 空间平衡：`b=max(1,ceil(c*sqrt(9*n/(512*s))))`，`c=1/2/4/8/16/32/64`。
- 块字节归一化：`b=max(1,floor(k*sqrt(n)/s))`，`k=1/2/4/8/16/32/64/128` 字节，先给共同预算 `B(n)=k*sqrt(n)`。

补测完成 109 个输入条件、16,350 次时间观测与 8,175 次内存观测。覆盖全部类型/主长度的均匀输入、额外 u64 增长长度，以及百万元素处的六种预声明压力分布。每条件同批重跑固定块策略和 LSD/Rust stable/TimSort/A/A，不混用两批时间。新系数未重跑初始全部 23 分布，具体覆盖见 README。

百万元素时，归一化组的块字节数在所有类型上均为 1–128 KiB，已覆盖 4 KiB 两侧，无需新增实验；固定 512 元素另作对照，仅对 8 字节元素等于 4 KiB。两类范围的元素块长也均逐类型跨过 512，审计读数如下：

## 空间增长与参数选择

全部 Block 内存观测均未超过实现上界 `2*R*b*s + 9*floor(n/b) + 66*R`。在 u64 均匀分布、n≥1,048,576 的范围，平方根系数 1 策略的 log(额外请求堆) 对 log(n) 描述性斜率为 **0.489**；这验证本次输入范围内的增长趋势，不代替复杂度证明。

最大实测输入为 16,777,216 个均匀 u64：固定 512 元素额外请求堆峰值 **2.297 MiB**，平方根策略 **1.516 MiB**，原 LSD **128.026 MiB**，TimSort **96.000 MiB**。

固定 512 元素的 scratch 随记录大小增长；固定 4 KiB 的 scratch 近似固定，但描述符随 n/b 增长；空间平衡平方根策略同时随输入长度和元素大小调整 b。初始九组数据和扩展参数均保留在 CSV；最终敏感性图采用补测的四类参数。本报告未根据同一数据挑选并宣称一个普遍最优默认值。

## 正确性与测量边界

Block 全部九组参数、Rust stable、TimSort 的完整排序输出均通过 oracle；配对输入摘要一致。另有浮点特殊值的独立位序检查。现有对照共有 **238 个算法标签×输入条件**未等于稳定 oracle（含 A/A 标签），均原样保留并在图中加叉；按算法：

- `dlsd`：56
- `lsd`：10
- `lsd_aa`：10
- `lsd_core`：28
- `lsd_plain`：42
- `thiel`：92

所有对照的 key 次序失败条件：0；数据 fingerprint 失败条件：0。fingerprint 是保留检查而非无碰撞证明；候选与两个稳定比较排序使用完整逐项比较。

A/A 对照共有 6,270 个配对时间比，整体中位数 0.9973；相对 1 的绝对偏差中位数 5.53%，P90 22.71%，P95 31.70%。接近此波动量级的差异不作为稳定性能收益。

正式测量子进程 2,090 个，退出失败 0；各进程结束时的 VmSwap 最大值=0 KiB；全系统同期 swap in/out 页数 2,553/0。系统计数包含其他进程，不可归因于排序。最大子进程 RSS=693.4 MiB。

时间与内存分别测量；两批 campaign 各自在固定 guest CPU 上单线程执行，比较仅在同批内进行。独立输入预热后的批量测量不代表冷启动。TimSort 是 C++ 实现，Rust stable 是本工具链的标准库实现，编译器和 FFI 差异必须随结果说明。没有做 p 值检验，也不把最小/最大范围当作置信区间。

A/A 按主长度分层如下，避免把极短调用中的开销和波动混入大数组的解释。A/A 同时包含方法标签分派及时间间隔的影响，是本 harness 下的变化参照。
