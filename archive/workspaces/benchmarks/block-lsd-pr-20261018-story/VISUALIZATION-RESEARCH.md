# 排序基准图法调研

问题是如何展示算法 × 数据类型 × 分布 × 规模，同时避免把工况间差异误画成计时不确定性。以下是对具体论文图表的观察，不代表所有学科的统一规定。

| 一手来源与具体位置 | 论文实际做法 | 对本数据的启示 |
| --- | --- | --- |
| [Axtmann 等，Engineering In-place (Shared-memory) Sorting Algorithms](https://arxiv.org/pdf/2009.13569)，§7.1、Table 1、Fig. 11/12 | 固定类型和分布画随规模变化的曲线；表格逐类型、逐分布列归一化慢速倍数；另用 performance profiles 总结跨工况表现 | 用分面分开类型，用连续规模轴画趋势；工况汇总与细节图承担不同职责 |
| [Dong 等，Parallel Integer Sort: Theory and Practice，PPoPP 2024](https://www.cs.ucr.edu/~yihans/papers/2024/PPoPP24/integer-sort.pdf)，Fig. 1、Fig. 4 | Fig. 1 固定 32-bit key/value 记录，热力表每格印数值；Fig. 4 用分组柱图做消融、折线图做规模/线程趋势，并分开 32/64-bit 情况 | 热力图可以用，但固定表示、限制密度并直接给数字比靠大片颜色估倍率更便于查证 |
| [Dolan 与 Moré，Benchmarking Optimization Software with Performance Profiles](https://arxiv.org/pdf/cs/0102001)，§2、Fig. 4.1–4.3 | 横轴为相对该工况最好算法的时间倍数，纵轴为满足阈值的工况比例 | 适合展示总体稳健性和慢速尾部；需要交代测试集与失败处理，不能代替具体退化条件 |

本次选择：主图按九种具体类型分面，固定 1M，23 个分布逐行画三个比较器的性能点；横轴为 Block 加速倍数，1 为胜负线。不同类型不再合成中心和范围。输入分布是类别，不用连线暗示连续趋势。重复计时只在同一工况内部汇总；图不把六次观测描述为六个独立随机数据集。

效率总览保留一个大输入的实际时间/堆代价、全部 1M 条件的内存计数，以及配对比的经验 CDF。后者与标准 performance profile 有联系，但这里以固定 Block 候选为分子、指定比较器为分母，可小于 1；因此准确标为经验分布，不冒称为相对全体最好算法的 Dolan–Moré profile。所有输入包括容易输入都保留；不照搬他文为了特定汇总而删除 sorted/zero 的选择。

原来的“跨类型 GM + min/max 线”移除了：线的来源是工况异质性，却采用了类似误差条的视觉编码；仅靠脚注说明不足以消除误读。随后尝试的无数值密集热力图也不作为交付图。最终图的跨工况 CDF、单工况重复计时范围、逐类型性能点分别标明统计对象。
