# 函数形式的数学依据

对当前 radix=8（R=256）的实现，令 n 为元素数、s 为元素字节数、b 为每块元素数。

辅助堆上界为 `M(b) = 512*b*s + 9*floor(n/b) + 66*256`。第一项是两个桶组的 scratch block，第二项是每个完整 block 的两个 u32 置换和一个 u8 usage。忽略取整后，求导并令导数为零可得：

`b_mem = sqrt(9*n/(512*s))`。

令总输入字节数 `S=n*s`、每块字节数 `y=b*s`，同一个式子写成：

`M(y) = 512*y + 9*S/y + 66*256`，`y_mem = sqrt(9*S/512)`。

这是辅助空间模型的连续最小值。对整数 block 需考虑取整；在小数组叶子、全相同/已排序输入或 bounded scatter 分支，上界也不一定取满。

时间模型不能直接等同于这个空间模型。当前 scatter 每趟处理 n 个元素，compact 的主要搬运量也为 O(n*s)；扩大 block 主要降低 O(n/b) 次 block/descriptor 管理。可以表达为：

`T(b) = T_scan_copy(n,s,d) + a*d*n/b + Phi(b,s,n,distribution,hardware)`。

只有在某个工作区间，额外代价 Phi 可近似成与 b*s 成正比时，求时间极值才会得到类似平方根的形式。源码不保证这个近似；c 必须靠计时确定。忽略固定项，采用 `b=c*b_mem` 后，两项空间和与最小空间之比为 `(c+1/c)/2`，c=4 对应 2.125 倍。因此 c 的含义是 scratch 与 descriptor 的取舍，不是已证明的最快参数。

现有筛选候选约等于：

`y(S) = max(1024, 4*sqrt(9*S/512))`，`b ~= y/s`。

约在 S=3.56 MiB 处从每块 1 KiB 过渡到平方根增长。实际候选仍使用原式的整数 ceil 与 floor，当前所有 s 都能整除 1024。

字节下限还有一个具体作用：当完整 scatter 的输入缓冲、融合 histogram、桶游标等全部堆量不超过 `512*b*s` 时，实现走 bounded_scatter。每块约 1 KiB 给这个门槛约 512 KiB 的预算，能让若干小输入切换实现路径。`n<=128` 则更早走稳定比较排序叶子。因此不能把跨实现分支的计时变化全部归因于一条光滑曲线。

从机制出发，更明确的未来候选是：小数组使用现有叶子；完整 scatter 所需堆在预设预算内时使用 scatter；其他输入使用 `c*b_mem`。若只能用 b 触发 scatter，最小充分块长约为 `ceil((n*s+H(d))/(512*s))`，H(d) 必须使用源码当前的完整 histogram 和游标预算。这个精确阈值策略尚未单独计时。

自由幂律 `b=A*n^alpha*s^(-beta)` 可用于检验平方根假设。若仅依赖总输入字节数选择块字节数，则应约束 `beta=1-alpha`。其空间上界中的两项随 n 分别为 `n^alpha` 和 `n^(1-alpha)`；固定 s 时，alpha=1/2 最小化最大增长指数。alpha=3/8 的自由拟合会让渐近主项变成 `n^(5/8)`，alpha=1/4 则为 `n^(3/4)`。这不表示在当前有限尺寸一定占更多内存，但不能保留 O(sqrt(n)) 的渐近宣称。

固定字节上限不自动等于 cache 最优。当前每个桶实际活跃的写入 cache line 与整个 scratch 分配量不同；不能仅凭 L1/L2 标称容量推出一个正确上限。长期截断增长还会让 n/b 项恢复线性增长。

109 个条件只有 35 种 (n,s) 组合，去除小数组叶子后为 30 种；大规模增长主要只测了 8 字节记录。同一个 n,s 的不同分布有不同的快块长。所以目标应是简单、稳健、空间代价可解释的策略，现有数据不能证明唯一的连续最优函数。

以上根据当前实现独立推导，并结合一次 subagent 只读审查；未新增排序计时。
