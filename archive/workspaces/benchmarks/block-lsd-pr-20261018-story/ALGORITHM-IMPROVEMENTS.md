# Block LSD 输在哪些路径，怎样改进

当前结论是存在可定位的改进机会；本图表包中的候选尚未实现、未计时。生产仓库保持原样。原版本固定为 e649c6af49d6bfdde896ca40cad387235fce4bfa，另保存到 archive/block-lsd-original-20261018 分支；后续候选在独立 research/block-lsd-adaptive 分支工作，不修改本包证据。参数筛选和现有对照无法证明新的实现一定更快。

## 已测差距与代码依据

1M/u64 的候选/LSD Stable 配对中位数：uniform 0.346，organ_pipe 3.539，push_front 3.772，push_middle 4.063，nearly_sorted 0.298。退化集中于特定输入结构，不能概括为随机数据上的 radix 核心普遍更慢。

同一原始批次的旧固定 4 KiB Block / LSD Stable / 无 Verge 的 LSD core，u64/1M，单位 ms：

| 输入 | Block 4 KiB | LSD Stable | LSD core |
| --- | ---: | ---: | ---: |
| uniform | 31.081 | 69.203 | 68.044 |
| organ_pipe | 36.947 | 3.839 | 39.593 |
| push_front | 15.647 | 3.874 | 36.382 |
| push_middle | 17.490 | 3.128 | 38.768 |

该表是原批次的接口/core 对照，不是 c4 的新消融。它与代码共同支持：LSD Stable 的优势很大一部分来自 Verge 对长 run 的识别和后续归并。Block 识别整个输入升序/降序后退出；局部结构通常继续进入 radix。两 run 归并仅为较短 run 分配缓冲，单个错位元素尤其有利。

另有两种不同原因：

- late_difference 的前 n−1 个键相等、最后一个更大，本来有序。first_different_key 扫到尾部后，check_order 又从头扫一遍，重复了已知相等前缀的读取。
- reversed 每键重复四次。Block 整段反转后还要修复等键组，才能保持记录 payload 稳定。现有 LSD 在两个 reversed-record 条件不满足完整稳定 oracle，已从同语义对比排除；不能靠删除稳定性修复追平它。

## 建议按复杂度递增推进

| 优先级 | 候选 | 保持的约束 | 收益假说与局限 |
| --- | --- | --- | --- |
| 1 | 复用方向探测已确认的相等前缀 | O(1) 状态；不改数据；转换 key 顺序一致 | 返回首个不同键的位置，从相等前缀末尾接续顺序检查；减少 late_difference 重扫。必须检查普通随机输入的向量化和分支开销 |
| 2 | 稳定的单元素错位修复 | O(n) 检测、O(1) 额外空间；确认后才旋转 | 优先处理 push_front/push_middle，省掉 radix 扫描与 scratch；无法解决多个错位或 organ_pipe |
| 3 | 受现有预算约束的 run 合并 | 只允许使用既有 scratch 预算；按转换 key 稳定比较；失败可回退 | 可能帮助 organ_pipe 和少量长 run；两条长度约 n/2 的 run 不能直接分配较短 run 全缓冲，旋转/块归并的工作量与复杂性必须实测 |

单元素候选可以用一般性判据，不能识别 benchmark 名称：找到第一个逆序相邻对 i−1,i；若去掉任意一个元素后序列有序，该元素必须在这一对中。分别验证两个候选，只有完整确认后才用二分定位并旋转。右移时插在后续等键之前，左移时插在先前等键之后，保留输入中的 equal-key 次序。验证失败不修改输入，直接继续 Block。常数次全扫描保持 O(n) 检测上界；随机输入应很早拒绝。实现仍需覆盖重复键、头尾边界和浮点转换 key。

不能直接套用现有 Verge + k_way_merge：多 run 情况会申请约 n/2 元素的缓冲，破坏本实现 O(b+n/b) 的辅助空间承诺；它还通过 PartialOrd 比较，和 Block 的转换 key 契约不能无条件互换。

## 最小验证范围

先逐个候选在独立实验分支验证完整稳定输出、payload/位模式保存和堆上界。重复键记录和特殊浮点位序是必要正确性案例。性能先选 late_difference、单错位、organ_pipe，以及 uniform/nearly_sorted 作为收益与退化对照；覆盖标量和宽记录，沿用 A/A、配对顺序、时间/空间分别测量。先筛小集合，失败即停止，不重跑完整矩阵。

用户明确要求：修复不能引起更普遍场景的性能退化。普通 uniform、偏斜、重复键、近乎有序和宽记录要分别检查；不能用总体 GM 的改善抵消某类常见输入的可重复损失，也不能把落在 A/A 波动内的小差异硬判为收益。候选只有在目标场景改善、普通场景没有测得稳定退化时才接受；有限测试仍不能证明所有可能输入都不退化。

正式新旧对比的两个实现使用完全相同的 c=4、最低 1 KiB 曲线，包含排序内部探测、修复、回退、申请释放；参数计算在外。不同修复独立消融，不把空间上限变化混入算法收益。旧实现固定分支与新候选保留，结果单独封存，不重写现有图表。

此处没有新算法性能结果，也没有启动新的算法实验。保留这些边界是为了把可证的多余工作、待测实现与已完成 benchmark 区分开。
